# NAS 屏幕伴侣

把飞牛 NAS 的运行状态（CPU / 内存 / 网络 / 存储 / 阵列 / 温度）以**只读**方式提供给局域网内的屏幕设备。管理界面在飞牛桌面里打开。

当前应用名为 **飞牛监控**，包名 `nasscreencompanion`，版本 **1.2.4**。面向 x86，最低 fnOS **1.2.0701**，依赖应用 `python312`。当前通过应用中心手动安装，尚未提交官方应用库。

从仓库根目录获取 [nasscreencompanion.fpk](nasscreencompanion.fpk)；大小与 SHA-256 见 [1.2.4 发布记录](../../docs/release-1.2.4.md)。固件构建、Wi-Fi 与端点配置见 [项目 README](../../README.md)，独立 SSH/systemd 采集器见 [nas/README.md](../README.md)。本应用默认 HTTPS 8798，独立采集器默认 HTTP 8799；`nas/install.sh` 不用于安装本 FPK。

管理服务使用普通包用户。1.2.0 起，生命周期由系统以 root 启动一个受限容器读取进程；随后立即降权运行管理服务。日常管理通过飞牛桌面完成。

---

## 它做什么

- 在 NAS 上常驻一个只读采集服务，按你设定的间隔读一次系统状态。
- 开一个供开发板读取的独立端口（默认 **8798**），默认 **HTTPS**。
- 在飞牛桌面里提供一个管理页：概览、能力矩阵、设备配对、服务设置、诊断五个标签页。
- 设备要先用**配对码**换到一枚令牌才能读数据；令牌在 NAS 侧只存 SHA-256，明文只在配对成功那一刻出现一次。

## 它不做什么

- **不写任何系统状态。** 采集全是读 `/proc`、`/sys`、`/proc/mounts` 这些只读来源。
- **不碰你已有的服务。** 尤其是开发版采集器（8799 端口、systemd 单元、`/usr/local/bin` 下的文件）——不在本应用管理范围内，安装、升级、卸载都不会改动或删除它。
- **端口冲突时不越界。** 如果你设的端口已被别的进程占用，应用会干净报错并告诉你是哪个端口，**绝不结束那个进程**。
- **不承诺 SMART / 硬盘健康。** 首版不读这些（权限与兼容性都还没验完）。
- **容器信息默认关闭。** 要读容器状态得显式打开（需要 Docker Socket，属于额外权限）。

## 安装

应用中心 → 手动安装 → 选择 `nasscreencompanion.fpk`。

安装向导的主要选项如下，都能在管理页调整：

| 向导项 | 默认 | 说明 |
| --- | --- | --- |
| 开发板读取端口 | `8798` | 按实际端口占用选择；独立采集器默认使用 8799 |
| 监听地址 | 内网所有网卡 | 选「仅本机」时管理页仍可用，但开发板读不到 |
| 开发板读取鉴权 | 配对令牌 | 「内网免令牌」只建议排障时短暂使用 |
| 传输加密（HTTPS） | 开 | 首次启动自动生成自签证书；关掉是明文，仅排障 |
| 采集容器状态 | 关 | 打开后通过受限辅助进程查询 Docker 状态 |
| 采集间隔 | 1.0 秒 | |

依赖：`python312` 应用。没装的话应用中心会提示。

### 升级已有安装

同样从应用中心手动上传新 FPK。升级保留已有服务设置、配对设备和 TLS 证书，不会用默认值覆盖它们；升级前处于运行状态才自动恢复启动。容器开关也保留原值，首次安装默认关闭。

升级脚本尝试在应用私有数据目录保留 `config.json.pre-<旧版本>`。出现备份失败提示时，不能视为已经备份成功。配置不可读、JSON 损坏或内容不是对象会明确停止，保留原文件，需先修复或恢复已确认的备份。不要为排障删除证书或递归放宽整个应用目录权限。

## 第一次打开

从飞牛桌面点开本应用 → 打开的是管理页。先看两个地方：

1. **「能力矩阵」**：逐项列出每个数据来源（`/proc/stat`、`/proc/meminfo`、`/proc/mdstat`、`/sys/class/hwmon`……）在**实际采集链路中**能不能读到，以及运行身份（uid/用户名）。哪一项是红的，就说明那类数据在这台机器上采不到——这一页就是权限的实测结果，不是承诺。
2. **「诊断」**：服务自检 + 日志尾巴。端口占用、证书状态、Socket 绑定都会写在这里。

## 硬件数量自适应

1.2.4 起，采集器默认完整提供存储卷、阵列、磁盘、温度通道、容器和网络接口清单。
接口速率分别按各自计数器计算；热插拔与计数器复位不会产生负速率。
`net.interfaces` 是现有协议的附加字段，旧固件仍可读取原来的默认接口摘要。

配套固件按实际条目数创建卡片，根据可用宽度换行，并滚动访问全部条目。
采集失败会保留上次数据并标旧值；来源没有权限时会显示来源状态。
名称、路径、设备与温度通道 ID 完整传送，不按设备型号或固定数量裁剪。
若显式配置采集数量策略，响应会提供总数和遗漏数量。

固件以可配置字节预算限制整帧与快照内存；超预算会明确报错并保留最后有效快照，
不会悄悄缩短清单。使用旧版应用时，固件只能显示旧应用实际提供的接口信息；
要看到所有网口，需要升级到本版采集器。

## 与开发板配对

三步：

1. **在 NAS 管理页「设备配对」点「生成配对码」**，得到 6 位数字。
2. **开发板先连接 Wi-Fi**，在配对面板填写 NAS 地址与本应用实际遥测端口（默认 8798），输入六位配对码，点「确认」。模板中的 8799 是独立采集器回退值，不能当作本应用的默认端口。
3. **核对指纹**：板子会把 NAS 证书的 SHA-256 指纹分 4 行显示，与管理页「传输加密」里显示的指纹**逐段比对**。一致才点「接受并配对」。

> **为什么要人工比对？** 板子只认这一张证书（证书固定），而"这一张"是不是你的 NAS，只能由你当面确认。指纹对不上就点「取消」——那说明中间可能有人在转发证书。
>
> 板子上的指纹是**自己**从证书算出来的，不是读服务器给的字段——否则同时伪造证书和那个字段就能骗过比对。

配对成功后，板子会把地址、令牌、证书写进自己的存储器，以后只走加密连接读数据。

**撤销设备**：管理页「设备配对」里对某台设备点「撤销」，板子下次读数据会被拒绝，需要重新配对。

## 换 IP / 换证书会怎样

- **NAS 换 IP**：板子按配对时记的地址连，连不上就会在总览页显示「连不上 NAS」，需要重新配对（或在板子上改地址）。
- **证书更换或重新生成**：指纹会变，固定旧证书的开发板将无法通过 TLS 校验，需要核对新指纹并重新配对。管理页「诊断」里能看到当前指纹；不承诺自动续签。
- **只关掉再打开 TLS**：**证书不会重新生成，指纹不变**，已配对设备不用重新确认。

## 常见问题

**装上以后开发板读不到。**
按顺序查：管理页「诊断」→ 端口是不是被占用（向导里设的端口和实际监听的是不是同一个）→ 监听地址是不是「仅本机」→ 开发板「配对」页显示的错误是哪一种（连不上 / 握手失败 / 令牌被拒，板子会分别给不同提示）。

**端口 8799 有东西在跑，要紧吗？**
那是开发版采集器，本应用不碰它。你可以继续用 8798。

**关掉 TLS 会怎样？**
遥测面变成明文 HTTP，任何人拿到令牌就能读。配对令牌仍然是必需的。**建议只在排障时短暂关闭**，诊断页会显示成 warn。

**卸载会留下什么？**
生命周期脚本停止本应用服务并清理 PID 与 Socket；应用数据是否保留由 fnOS 卸载流程处理。删除数据会丢失 NAS 侧配对记录与证书，重装后开发板需重新配对。开发板固件与 NVS、独立采集器和其他服务不在本应用卸载范围内。

## 装不上、起不来的时候

这两件事最可能发生在你面前，而这时你还看不到管理页。下面按**你看到的那句话**来查。日志为 `$TRIM_PKGVAR/info.log`，可通过正式绑定 `/var/apps/nasscreencompanion/var/info.log` 定位；数据卷由 fnOS 决定，不写死 `/volN`。优先使用应用中心「查看日志」，私有目录不一定允许普通 SSH 用户读取。

### 安装时被拦下

| 你看到 | 意思 | 怎么办 |
| --- | --- | --- |
| 「端口 8798 已被占用。请回到向导换一个端口再安装；**本应用不会结束占用该端口的进程**。」 | 你要的端口上已经有东西在跑 | 回到向导换一个端口。想知道占用者是谁，可以用「诊断」页（应用已经在跑的话）或 `ss -ltnp` 看一眼——**本应用不会替你去杀它** |
| 「未找到 python312 运行时（依赖应用可能还没装好）」 | 依赖的 Python 应用没装 | 先在应用中心装 `python312`，再装本应用 |
| 「检测到 8799 上有服务（应为开发版采集器）」 | 只是提示 | 不需要处理。两者可以并存，本应用用 8798 |

### 启动成功、但应用中心里点开是空的

这时**遥测接口是好的**（开发板照常读数据），坏的只是管理面。启动日志里会有这两句：

```
服务已启动，但管理面 Socket 没有出现：…/target/app.sock
应用中心里点开本应用会打不开，请看 info.log 里的绑定失败原因。遥测接口不受影响。
```

原因通常是 target 目录不可写，或者路径过长。`info.log` 里有具体的 errno。**开发板不受影响**，不用急着卸载。

### 启动了但读不到数据

先看管理页「诊断」标签页——它会逐项报告：

- **网关 Socket / Socket 权限**：管理面本身是否正常
- **遥测端口**：实际监听在哪个端口
- **鉴权模式**：是配对令牌还是内网免令牌
- **遥测面 TLS**：启用/关闭/失败，失败时会写出原因
- **首次取证书通道**：明文只放行 `/api/v1/identity`
- **运行用户**：真正跑着的 uid（应该是专用包用户，不是 root）
- **开发版端口 8799**：只报告，不触碰

### 「进程存在（pid …）但端口 … 无响应」

`main status` 会这么报（退出码 1，中间是实际的 pid 和端口号）。多半是端口被别的东西抢了，或者进程卡在启动中。看 `info.log`。

停止时如果优雅等待（10 秒）超时，会升级到 SIGKILL；**发完信号之后还会再看一眼**，
确认进程真的没了才说「已停止」。万一它卡在不可中断状态（D state）杀不掉，你会看到
「进程 … 在 SIGKILL 之后仍然存在」，`stop` 返回非 0——这时端口可能还被占着，
用 `ps -p <pid> -o pid,stat,cmd` 看它的状态。**不会出现"说停了其实还在跑"。**

## 数据来源与运行身份

| 数据 | 来源 |
| --- | --- |
| CPU / 负载 / 进程数 | `/proc/stat`、`/proc/loadavg` |
| 内存 / 交换 | `/proc/meminfo` |
| 网络速率 | `/proc/net/dev`、`/proc/net/route` |
| 卷容量 | `/proc/mounts` + `statvfs` |
| 阵列 | `/proc/mdstat` |
| 磁盘 IO | `/proc/diskstats` |
| 温度 | `/sys/class/hwmon/*/temp*_input` |
| 容器（可选） | `/var/run/docker.sock`，只调 `GET /containers/json` |

运行身份是**专用包用户**（`run-as: package`），不是 root。所有读取都是只读的；读不到的段会标注状态而不是静默给 0。**采样**的每段状态是 `ok` / `stale`（本次失败、沿用上一份旧值）/ `missing`（来源不存在）/ `denied`（权限不足）/ `error`（读到了但解析失败）/ `disabled`（被配置关掉，比如容器）；**能力矩阵**里每段还有 `partial`（部分可读，比如只有一部分温度传感器读得到）。

## 开发板侧的接口

供自研屏幕设备使用，三个端点：

- `GET /api/v1/health` — 存活探针
- `GET /api/v1/status` — 当前状态快照
- `GET /api/v1/history` — 最近若干采样

首次取证书：在**同一个端口**上，明文连接只放行 `GET /api/v1/identity`（返回证书 PEM），其余任何路径一律 403——因为设备在固定证书之前建不了 TLS。证书是公开信息，这一步不泄漏新东西；信任仍然建立在上面那次**人工指纹比对**上。

## 怎么打包

以下开发命令均从**仓库根目录**执行。需要 Python 3、Bash、`tar`，打包需要 PATH 上的 `fnpack`；管理页 VM 回归需要 Node.js。固件与主机预览另需 ESP-IDF 和 CMake 环境。

```sh
bash nas/fpk/build.sh
```

**别直接跑 `fnpack build`**：它会把包目录里的一切塞进包里，包括开发机上跑过服务端之后留下的 `__pycache__/*.pyc`（本机 Python 版本的字节码，而 NAS 上是 python312）。`build.sh` 会先清理、再打包、打完立刻扫一遍产物。

`bash tools/test_report.sh` 会运行较广的检查并**覆盖** `docs/fnos-companion-test-report.md`；使用前准备好其所需的固件、预览及本地长测环境。生成报告与各阶段记录分别保留，不能把跳过的项目写成当前通过。

装机之后、接板子之前，建议先跑：

```sh
# 替换地址；将管理页刚生成的码放在自己的本地环境中。
python3 nas/fpk/board_sim.py --host nas.example.test --port 8798 --pair-code "$FNOS_PAIR_CODE"
```

它测试证书获取、固定证书后的 TLS、错误证书拒绝、配对及带令牌的状态请求。**会消费配对码并创建测试设备记录**，完成后可在管理页撤销该测试设备。自动固定读取到的证书不能独立验证 NAS 身份，运行前仍需通过可信管理页人工核对证书指纹。

字段清单以 `board_fields.json` 与 `contract_check.py` 为准，1.2.4 基线为 60 个字段。模拟器核对真实 NAS 响应，不用 macOS 的源码回退冒充 Linux 采集结果；来源状态仍需结合能力矩阵查看。

## 容器采集与升级保留

服务设置中打开「采集容器状态」后，会读取运行和停止的容器。Docker 查询每 5 秒刷新一次，模块时间戳保留真实读取时间；读取失败只保留最后一次有效快照，并标为陈旧。关闭、权限不足、来源缺失和读取失败不会再显示成健康的空列表。

Docker Socket 本身拥有完整 Docker 控制权限，因此不会把管理服务加入 docker 组。辅助进程位于系统 root 所有且包用户不可写的 `cmd/docker_launch.py`，使用系统 `/usr/bin/python3 -I` 运行，只接受继承 socketpair 上的单字节读取指令，只调用固定的 `GET /containers/json?all=1`，返回名称、运行状态、状态描述、总数和读取时间。它没有网络监听端口，不接受任意路径、方法或命令，也不转发 Docker 的环境变量、挂载或网络详情。

辅助进程读取有时间和字节上限；服务退出后连接关闭，辅助进程随之退出。配置、日志、PID、证书和可写 target 代码均由普通包用户访问。系统 Python 或 root 代码信任检查不通过时启动失败；不会把管理服务改为 root 运行。

升级保留现有配置、配对设备和 TLS 证书，容器开关也保留原值；安装后仍需在服务设置中显式启用容器采集。

1.2.1 补齐 fnOS 在 root 模式安装或升级时重置数据 ownership 的兼容处理。启动和配置写入前，root 持有的入口从自身包 manifest 验证应用名，再经正式 `/var/apps/<appname>` 的 `var` / `etc` 绑定动态定位数据卷，兼容临时解包目录执行升级脚本。通过目录文件描述符迁移私有目录为包用户 `0700`、普通文件为 `0600`。拒绝符号链接、硬链接、其他用户文件和特殊文件，保留文件内容；目录遍历期间封闭 ACL 写入窗口，成功或异常都交回包用户。随后以服务实际 UID/GID 验证日志和数据可访问性，失败原因通过应用中心前台显示。

1.2.2 修复桌面管理入口，并保留服务设置的未保存草稿；保存使用点击时的字段值。1.2.3 在覆盖安装时保留已有配置；读取拒绝、JSON 损坏或非对象配置会明确停止，保留原文件，不会写回默认值。首次没有配置文件才初始化默认值；用户明确提交关闭容器采集仍正常生效。

权限迁移回归：`python3 nas/fpk/startup_permission_check.py`。它使用临时合成数据验证证书和备份内容保留、重复执行、链接及特殊文件拒绝、权限设置失败后的恢复；实际 root 权限和降权仍需安装后在 NAS 验证。

配置保留回归：`python3 nas/fpk/config_persistence_check.py`。验证覆盖安装、升级、明确关闭，以及读取或格式错误时原文件不被替换。配置损坏时请先备份并修复 JSON，或恢复已确认的升级备份，再重新启用应用。

本地回归：`python3 nas/fpk/docker_check.py`；生命周期：`bash nas/fpk/test_lifecycle.sh`。macOS 检查覆盖 Unix HTTP/IPC、缓存、新鲜度和各生命周期行为，实际 Linux 身份降权与 Docker 权限需在 NAS 验证。
