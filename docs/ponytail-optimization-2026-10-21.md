# Ponytail 数据路径优化

基线：`16ba598`，发布目录未提交差异；使用 Ponytail full。优化状态快照字符串复制和历史行读取，不改变接口、协议、页面、采样节拍或清单数量策略。

## 改动

- `fnos_snapshot.c`：JSON 字符串直接复制到快照所有者，省去两次 `vsnprintf`；缺失和空字符串复用常量空串。格式化接口仍服务真正需要格式化的调用，非空字符串保留独立所有权、字节预算与失败时整帧拒绝。
- `fnos_data.c`：每条历史行按 cJSON 链表顺序读一次，替代按列反复从头查找；保持数字有限性、范围、时间戳和可选温度校验。
- 同步解析提取器；补充稀疏清单、短行、非法字段类型和额外列回归。
- 修复既有历史测试桩：包含首页温度图，覆盖五张图的清空与六条曲线；负对照接受容量累加任一对应有限性断言先触发。

## 测量

Mac 主机、`cc -O2`，同一匿名输入（192 温度通道、96 容器、64 磁盘、24 卷），每组 2000 次解析和释放、重复三次。基线源码副本与 Git HEAD 按字节比对一致。

| 指标 | 基线 | 优化后 |
| --- | ---: | ---: |
| 每帧快照分配次数 | 1051 | 833 |
| 每帧快照申请字节 | 41926 | 38220 |
| 2000 次解析 CPU 耗时中位数 | 467.455 ms | 317.967 ms |

快照分配减少约 20.7%，申请字节减少约 8.8%，该主机样本 CPU 耗时减少约 32.0%。分配统计仅包含快照层，时间包含 JSON 解析和释放；均不等同于 ESP32-P4 性能或整机内存测量。本地复现材料与输出在 `logs/ponytail/benchmark.c`、`benchmark.json`、`benchmark-results.txt`，不随源码发布。

## 验证

- `snapshot_check`：直接编译生产解析器，ASan/UBSan 通过；覆盖长名称、并发读者、替换/缩减、无效输入、可选指标、时间元数据和超预算后保留旧快照。新增半预算稀疏清单用例在原实现失败，在优化后通过，未放宽预算。
- `python3 tools/test_history.py`：14 个历史场景及时间顺序、整数收窄负对照通过。
- `python3 tools/test_history_merge.py`：11 个历史合并场景、真实 pthread 锁、OOM、游标失效、空批次重置以及图表边界/负对照全部通过。
- `bash tools/parsecheck/run.sh`：818890 字节匿名状态帧、20174 个字符串字段、900 行历史及最后 600 行回读通过。
- ESP-IDF 5.5.3 / ESP32-P4：`./idf.sh build` 完成；实际交叉编译命令加 `-O0 -fanalyzer` 检查两个生产 C 文件，均退出 0、零诊断。
- `git diff --check` 通过；Ponytail Review 对照调用方、快照所有权、失败路径和完整差异复核，无待修发现。

构建助手从缓存恢复芯片参数后误执行 `set-target`；本地配置已从其备份恢复并核对原显式配置值，再通过项目入口完成编译。未修改全局技能。

未执行烧录、物理屏幕验收或实机性能测试；未提交、推送或同步开发目录。开发目录原有 UI 改动保持独立。
