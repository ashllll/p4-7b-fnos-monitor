# Refactoring UI 视觉优化与验证

本轮在已验收的 Device 风格和动效上继续优化五个 NAS 页面及配对、Wi-Fi、诊断覆盖层。
实际实现是 C/LVGL；开发工程为 `p4-7b-fnos-monitor`，资料仓中的示例没有改动。

使用 [gnurio/refactoring-ui-plugin](https://github.com/gnurio/refactoring-ui-plugin)，
读取版本 `00781eab1dde7fdb720d63f8d6c8148bf5835a31` 的 `meta-refactor-ui`、
`establish-visual-hierarchy`、`manage-color-contrast`。
按总评技能的十项分类检查，重点落实层级和对比度；其余分类结合实际版面定向判断。
所有修改复用原生字体、颜色令牌和自适应布局。
后续卡片间距整改使用同版本的 `apply-consistent-spacing` 技能。

## 问题与处理

| 检查角度 | 原问题或现状 | 本轮结果 |
| --- | --- | --- |
| 视觉层级 | CPU 当前值不显眼，系统页巨大装饰标题占位 | CPU 提升到现有 32px 字级，紧凑视口使用 20px；系统标题改为实际采集状态 |
| 字体尺度 | 导航和主卡辅助内容偏小 | 导航使用 16px；主卡辅助文案按视口在 12/16px 间适配 |
| 色彩系统 | 按钮填充色和文字色缺少成对语义 | 增加 `on_primary`、`on_danger`，四主题分别设置合适前景 |
| 间距 | 系统空告警和卡片内边距挤占列表空间 | 使用已有 4/8px 间距级别；空告警高度由字高和卡片结构计算 |
| 按钮层级 | 配对确认的浅桃色底配浅色文字 | 修正主按钮及按下态文字，保留边框与位移反馈 |
| 视觉杂讯 | 重复英文标记、强边框、列表随序号逐渐变暗 | 去掉冗余标记，减弱普通边框，列表使用统一底色 |
| 空状态 | 零告警的大块空白 | 收缩空告警卡；未采集、旧值、权限不足仍分别显示 |
| 阴影 | 当前阴影主要用于告警和状态反馈 | 保留现有用途，未增加装饰阴影或渲染图层 |
| 对比度 | 夜间容量数值、主卡小字、列表副文、确认按钮偏暗 | 修正前景与背景；全部稳态样例按 4.5:1 检查 |
| 相关内容分组 | 系统清单显示面积不足，列表重排后顺序翻转；网络长接口名挤压统计分栏 | 释放空告警空间，保留采集器顺序；网卡信息均衡分栏，标识采用 16px 字级 |

1024×600 的健康系统页采用容器与硬件温度并排布局，列表内容按实际高度滚动查看。
800×480 按实际高度使用双列卡片和滚动；1280×800 可展开更多完整行。
温度页依旧由用户手动展开具体设备，定时采样只更新读数。
系统“无采集告警”仅表达采集器未上报告警，不推断所有硬件都正常。

共享列表重排原来倒序取出列与行，再以追加方式放回池中，改变了阅读顺序。
现在正序恢复并插到新行之前，无需额外分配；新增容器后也保持原采集顺序。
预览中另修正健康阵列样例，使 `ok`、成员数、同步进度和 `clean` 文案相互一致。
健康网络样例使用协议允许的最长 15 字符匿名接口名，覆盖真实设备发现的分栏空间问题。
接口名保留完整数据并按列宽显示，读数仍使用 20px 字级，吞吐图区获得更多高度。

## 对比度证据

使用 sRGB 相对亮度公式，合成实际背景层与文字透明度。
以下为样式色计算结果，照片的曝光和面板色偏不参与这些数字。

| 检查位置 | 优化前 | 优化后 |
| --- | --- | --- |
| Device 夜间桃色容量卡文字 | 2.29:1 | ≥5.51:1 |
| Device 主卡小字 | 最低 3.42:1 | 最低约 4.64:1 |
| Device 桃色主按钮文字 | 1.41:1 | 6.68:1 |
| Graphite 主按钮白字 | 临界低于 4.5:1 | 4.89:1 |

新增语义前景在配对确认、Wi-Fi 连接、键盘确认、主/危险按钮等调用点统一使用。
夜间桃色卡加深背景并切换文字色，退出夜间时恢复白天语义色。
四主题主/危险按钮的正常和按下态均通过目标值。

## 构建与实机

ESP-IDF 5.5.3 / ESP32-P4 rev3.x 构建通过，应用镜像 1,795,568 字节，应用分区余量 81%。
当前 ELF 的四个任务入口静态栈预算通过，LVGL 任务约 61%；静态分析不能替代运行期栈水位。
通用构建辅助脚本本轮只执行了目标配置，没有生成 ELF；最终通过工程已验证的 `./idf.sh build` 完成。

最终固件以已确认串口、230400 波特率烧录，三个分段均通过写入校验。
随后由单一串口进程执行五页切换并取得相机取景；六次切页回显全部确认，七张新取景均已实际查看。
总览、存储、网络、系统、温度的顶栏名称与导航选中项一致，未见错位或前页残留。
网络长接口名已与累计统计分开；系统容器与硬件列表正常显示，温度保持手动展开。

两次间隔约 35 秒的总览取景中，运行时长分钟、轮询数和网络读数/曲线继续更新。
串口周期记录达到 90 次成功轮询、0 次失败，未见 panic、断言、栈保护或看门狗报错。
这是本轮观察窗口内的结果；相机有摩尔纹、反光与透视，静态取景不能证明帧率或无撕裂。
用户先前验收的动效继续保留。本轮视觉修改完成设备观察，尚未据此代替用户的主观验收。
相机截图、原始串口记录和固件仅留本地。

## 卡片间距整改

针对“卡片之间过于靠近”的反馈，新增统一的 `UK_CARD_GAP`：正常视口为已有 12px 阶梯，
低于参考屏高的紧凑视口使用 8px。总览、存储、网络、系统、温度的主要卡片横纵间距均使用该令牌。
卡内相关文字仍使用较小间距，总览状态行与资源卡归入同一 flex 分组，避免矮屏浪费高度。
分组最小高度由字体与子卡片最小高度计算；紧凑视口隐藏空的弹性占位，保留全部读数和图区。

温度设备块单独增加行间隔；池的列高、可容纳行数与尾部间隔预算同步使用实际样式间距。
该次整改仅处理主要卡片和温度设备组；随后按用户反馈继续处理下面的内部小卡片间距。
池预算使用实际间隔，不会重复计入最后一行之后的间隔。

最终增量为 `fnos_ui.c`、`ui_kit/uk.c`、`ui_kit/uk.h` 三份源码。
三尺寸各 75 张原生静态样例通过；151/71/96 帧的输入、首次布局及重复目标回归通过。
已查看正常与紧凑总览、系统、温度，以及 48 通道展开后的末行样例。
ESP-IDF 构建与四任务入口静态栈预算通过，应用镜像 1,796,336 字节，应用分区余量 81%。

最终镜像以 230400 波特率烧录，三个分段写入校验通过。
随后取得并实际查看七张新相机取景：五个页面均显示新间距，六次切页回显确认，导航与页面匹配。
两次相隔约 35 秒的总览取景中，时钟、读数、曲线和轮询数继续更新；串口周期计数达到 90 次成功、0 次失败，
未见 panic、断言、栈保护或看门狗报错。相机取景含透视、反光和摩尔纹，仅用于本轮版面与运行观察。
原始取景、串口日志与个人固件继续仅留本地。
DSH Desktop 对三份最终哈希完成只读定向复核，未发现需要修改的确证缺陷；
候选的滚动与初始列高预算问题经核对均未确证为此次回归。复核工作流已收尾，未扩大到其他未提交工作。

## 内部小卡片间距整改

针对系统、存储内部小卡片仍拥挤的反馈，为卷、阵列、磁盘、容器、系统温度五个列表设置
`UK_ITEM_GAP`：正常视口 8px，紧凑视口 4px，小于主要卡片的 12/8px 间隔。
条目左右内边距使用 8px，上下使用 4px；五个列表保持条目自然高度，减少列内弹性拉伸。
共享条目构造按父池实际行距选择内边距，Wi-Fi 的紧凑池继续使用既有样式。

系统页根据当前条目自然最小高度、标题、内边距和间隔估算能否显示两条完整记录。
有足够高度时纵向展开，否则容器和温度并排；无告警时把空事件卡收为单行。
两列模式使用整个剩余列表高度判断空事件卡的预算，800×480 也能保留完整条目和可滚动空间。
内容较多时允许露出下一条的部分内容提示滚动，完整末行可达；没有靠压缩文字来容纳全部记录。

最终三尺寸各 75 张静态样例通过，共 225 张；151/71/96 帧输入、首次系统布局、重复目标回归通过，
