# KKUI 监控界面重构 v7

日期：2026-10-05。开发工程：`<project-dir>`。

## 页面与设计

基于当前手写 C + `kk_ui` 构件实现，沿用现有视觉令牌；没有恢复 JSON/MVVM 生成管线或增加框架依赖。
信息组织参考 [Beszel](https://github.com/henrygd/beszel)，导航与状态摘要参考 UniFi，曲线表达参考 [Grafana Node Exporter Full](https://grafana.com/grafana/dashboards/1860-node-exporter-full/)。

- 总览：可信度与健康结论 → CPU、内存、最高温度、网络下行四项 KPI → 资源趋势、卷容量摘要、运行与事件摘要。
- 存储：已用、总量、可用容量 → 存储卷、阵列成员/同步进度、磁盘读写。容量为采集到的卷数值合计，不代表物理磁盘原始容量。
- 网络：上下行、合计速率、采集延迟 → 同一量程的双曲线 → 接口与轮询统计。
- 系统：容器、温度、告警三列。页头“采集诊断”打开诊断面板，再次点击返回；保留 HTTP、最近错误、数据年龄、固件内存和 ZFS 信息。

主数值 44px，网络页混排数字 30px，导航与主要标签 18px，明细 15px。导航点击区域 60×78px，诊断按钮 148×48px。列表使用 LVGL 原生纵向滚动，可访问数据层的完整上限：8 卷、6 阵列、8 磁盘、10 温度、12 容器、8 事件。

## 状态与指标

- 无有效快照时使用 `-` 和“等待数据”，不将零值伪装成有效指标。
- 离线时保留最后成功快照，页头明确标注旧数据与年龄，健康结论优先显示离线。
- 最高温度遍历 CPU 与全部已采集温度传感器；温度缺失显示不可用。
- CPU/内存双曲线固定 0–100%；网络双曲线共享量程并显示上限。
- 曲线按最近 180 次成功采集显示。数据层没有采样时间戳，离线后无法证明覆盖固定三分钟，因此界面不使用“近三分钟”标签。
- 用量条在 80%/90% 提示/危险，温度条在 60°C/75°C 提示/危险。语义颜色与数值序列色分开。
- 告警变为零条时隐藏所有旧事件；数据层锁超时保留上一帧，避免未初始化快照覆盖界面。

