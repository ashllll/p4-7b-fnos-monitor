# 界面改版设计合同（v2）

按 `cuktech-screen-ui` 技能的要求，先写清合同再动像素。旧版（v1）是"能看"的仪表盘，
这一版要解决的是**信息层级、状态编码与实机可读性**，不是加装饰。

## 1. 设备合同

| 项 | 值 |
| --- | --- |
| 板卡 / 面板 | Waveshare ESP32-P4-WIFI6-Touch-LCD-7B，7 寸 IPS 1024×600 MIPI-DSI（EK79007），GT911 单点触摸 |
| 方向 / 观看距离 | 横屏固定（ROTATE_180），桌面 40–80 cm |
| 图形栈 | LVGL 9.5 + esp_lvgl_adapter，**全屏 partial buffer**，无独立合成缓冲 |
| 输入 | 触摸：左侧导航点选 + 内容区左右滑动翻页 |
| 刷新预算 | LVGL 任务 12 KB 栈（PSRAM）；内部 RAM 稳态 239 KB；数据 1 Hz，曲线视觉推进 ≤2 fps |
| 夜间 | 23:00–07:00 背光 12% |
| 短边 S | 600 px（版面比例全部由 S 推导） |

## 2. 数据合同

| 值 | 单位 | 来源 / 周期 | 有效窗口 | 零值 | 缺失 |
| --- | --- | --- | --- | --- | --- |
| CPU | % | `/proc/stat` 差值 1 s | 3 s | 真 0% | `--` |
| 内存 | % / GB | `/proc/meminfo` 1 s | 3 s | 真 0% | `--` |
| 温度 | °C | hwmon 1 s | 5 s | 不可能 | 该行不画 |
| 存储用量 | % / TB | `statvfs` 1 s | 10 s | 真 0%（/vol4） | 该行不画 |
| RAID | 状态词 | `/proc/mdstat` 1 s | 10 s | — | 不画 |
| 网络吞吐 | KB/s（1024 基数） | `/proc/net/dev` 差值 1 s | 3 s | 真 0（空闲） | `--` |
| 容器 | 状态词 | docker.sock 5 s 缓存 | 15 s | — | 不画 |
| 采集可信度 | — | 本轮 HTTP 结果 | 见 §4 | — | — |

单位换算：一律 1024 基数（KB/s → MB/s 在 1024 处切换，带 2 s 迟滞避免 999↔1.00 抖动）。
精度：吞吐 `0.0`（<100）/ `000`（100–1023）；百分比整数；容量 1 位小数（TB/GB 自动）。

## 3. 页面问题（每页只回答一个）

| 页 | 问题 | 第一眼 | 第二眼 | 第三眼 |
| --- | --- | --- | --- | --- |
| P0 总览 | NAS 现在健康吗？ | 健康结论（正常/注意/危险）+ 告警条数 | CPU / 内存 / 最高温 / 运行时长 四块遥测 | 6 个存储空间占用条 + CPU·内存趋势 |
| P1 存储 | 空间还够吗？阵列坏没坏？ | 总可用容量 Hero + 容量堆叠条 | 每个存储空间的用量行（含 80%/90% 阈值刻度） | RAID 状态 + 磁盘读写活动 |
| P2 网络 | 现在快不快、稳不稳？ | DOWN / UP 双主值 | 双轨趋势（低透明度面积 + 稀疏参考线） | 累计收发、接口名、采集延迟 |
| P3 系统 | 谁在跑、多热、数据可信吗？ | 容器清单（状态点 + 名称 + 状态词） | 温度矩阵（热条 + 阈值刻度） | 采集端点自检：HTTP 耗时 / ok-err / 数据年龄 / Wi-Fi / 内存 |

## 4. 状态编码（三层，互不覆盖）

- **身份色**（跨页稳定）：CPU `#3FA9F5`、内存 `#37C4D6`、温度 `#FF7A1A`、存储 = 能量渐变、网络 DOWN `#37C4D6` / UP `#3FA9F5`、ZFS `#C8E63C`。
- **运行状态**：`idle`（休眠/零负载，数值降灰但保留对象名）、`active`（有读数）、`alert`（保留身份色 + 红/橙描边 + 状态词）。
- **可信度**（页面级 + 对象级）：
  | 状态 | 触发 | 面板表现 |
  | --- | --- | --- |
  | `warming` | 开机首个样本未到 | 数值 `--`，顶部胶囊"等待数据"（黄） |
  | `live` | 最近一次轮询成功且年龄 < 3 s | 不额外着色 |
  | `stale` | 有值但年龄 ≥ 3 s | 数值降到 62% 不透明度 + 胶囊"陈旧 Ns"（黄） |
  | `offline` | 最近一次轮询失败 | 胶囊红"采集端离线" + 底部红字给出具体错误（connect/timeout） |
  | `no-data` | 字段缺失 | `--`，绝不用 0 冒充 |
  真实 0（`0 KB/s`、`0%`）与 `no-data`、`offline` 严格区分。

## 6. 版面骨架

```
┌ 顶栏 h=64 ────────────────────────────────────────────────────────────┐
│ NAS nas · <NAS_IP>        [ ● 在线 ]  数据 0s        Wi-Fi ▂▄▆ 12:34 │
├ 导航 w=104 ─┬ 内容区 (S-104-2*20) ───────────────────────────────────┤
│ ▍总览       │  各页按 §3 的"第一眼→第二眼→第三眼"自上而下              │
│  存储       │                                                        │
│  网络       │                                                        │
│  系统       │                                                        │
├ 底栏 h=40 ───────────────────────────────────────────────────────────┤
│ 采集 <NAS_IP>:8799 · ok 570 / err 0 · 20 ms   [告警条] RAID md127 降级 │
└──────────────────────────────────────────────────────────────────────┘
```

- 顶栏左：主机名 + 端点；中：可信度胶囊；右：Wi-Fi 信号条 + 时钟。
- 底栏左：轮询统计；右：**告警带**（严重度色块 + 一行文案），无告警时显示"无告警"（绿）。
- 导航项：图标（几何绘制）+ 中文标签 + 选中态（左侧 3px 身份色条 + 底色）。页面指示器只用位置表达。

## 7. 动效规则

| 场景 | 时长 | 做法 |
| --- | --- | --- |
| 触摸反馈 | 60 ms | 导航项底色一次性高亮 |
| 切页 | 原子换页（0 ms 位移） | 先隐藏全部旧页并把偏移归零，再显示目标页，最后整屏失效 |
| 新告警进入 | 300 ms × 1 次 | 告警带胶囊一次脉冲，不持续闪烁 |
| 数值刷新 | 直接切换 | 1 Hz 数据不做插值滚动，避免读数抖动 |
| 趋势 | 随样本推进 | 仅新点进入，不按负载改变横向速度 |

> 依据技能里"已验证故障模式：切换界面残留"：本板是"全屏页 + partial buffer"，**不做**双页同时滑入滑出，
> 只用原子换页；若日后要用滑动动画，必须先有整屏失效或单合成缓冲。

## 8. 首帧与背光

上电顺序改为：面板初始化 → 绘制静态首帧（`等待数据` 状态）→ 等首个 flush → 再开背光，
避免"背光先亮、内容未到"的随机画面。

## 9. 验收合同

| 证据层级 | 本项目做法 |
| --- | --- |
| 结构 | 本节设计合同 + 版面常量集中定义 |
| 构建 | `./idf.sh build` 通过，字号/字体无告警 |
| 烧录 | `idf.py flash` + hash 校验 |
| 运行 | 串口：首帧、首个样本、轮询统计、无断言 |
| **实机视觉** | 手机固定机位逐页拍照 + 肉眼判读：裁切、字糊、色偏、对比度、切页残留 |

不得用"构建成功/烧录成功/串口正常"替代实机视觉验收。
