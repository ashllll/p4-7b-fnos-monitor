# 界面 v6：UniFi 设计语言重构（设计合同）

> 需求：**完全引用 UniFi 的设计语言重构当前 UI**（视觉体系 + 信息架构一起换）。
> v5 的 KK 体系（深蓝分层 + 内嵌标题条 + 饱和色块 + 16px 圆角卡）在本文档生效后作废；
> `docs/ui-kk.md` 仍然有效的是**结构契约**（MVVM-C、JSON→C 生成管线、Store/Binder 边界），
> 视觉部分以本文档为准。

## 0. 一句话

把「NAS 监控面板」画成 **UniFi Network 控制台**：近黑画布 `#131416` + 靠**表面色阶**
（`#131416` → `#1C1E21` → `#282B2F`）分层的卡片（8px 圆角、不画边框）、
**唯一品牌蓝 `#006EFF`** 只表示"可交互/选中"、状态一律用**中性胶囊 + 小实心色点**、
图表只有水平网格线且无边框无坐标轴、字体只用 400/600 两档且 600 落到 Medium。
信息架构从 4 页重排成 UniFi 控制台的 5 段：**总览 / 存储 / 服务 / 流量 / 系统**。

## 3. 字体阶梯

真身是 Ubiquiti 专有 **UI Sans**，回退栈 `Inter, Lato, Arial, sans-serif`；本工程用的就是 Inter。
UniFi 的排版体**只有 400 与 600 两档，且 600 实际渲染为 Medium**——所以**不上真 Bold**。

| 资产 | v5 | **v6** | 对应 UniFi |
| --- | --- | --- | --- |
| `font.hero` | num 56 SemiBold | **Inter-SemiBold 44** | xlarge-4（35）在 7" 上的放大档 |
| `font.numL` | num 44 SemiBold | **Inter-SemiBold 30** | xlarge-3（27） |
| `font.numM` | num 28 Medium | **Inter-SemiBold 22** | xlarge-2/1（23/19） |
| `font.numS` | num 17 Medium | **Inter-Medium 16** | large（15） |
| `font.label` | txt 15 Medium | **Inter-Medium 14** | body/label（13） |
| `font.meta` | txt 13 Regular | **Inter-Regular 12** | caption（11） |
| `font.cjkVerdict` | cjk 40 Medium | **NotoSansSC-Medium 30** | 健康结论 |
| `font.cjkTitle` | cjk 24 Medium | **NotoSansSC-Medium 20** | 页标题 / 卡标题 |
| `font.cjkLabel` | cjk 17 Medium | **NotoSansSC-Medium 15** | 行名 / 标签 |
| `font.cjkMeta` | cjk 13 Regular | **NotoSansSC-Regular 13** | 中文次要（中文下限） |

* **字距一律 0**（UniFi 令牌集里没有 letter-spacing），不再使用 v5 的 `letterSpace` 技巧。
* **不用大写标签**。
* 字号比令牌大一档的原因：1024×600 / 7" 的观看距离比桌面显示器远，且本板 DPI≈130；
  阶梯的**相对比例**按令牌 1:1 保留。
* 改字号后必须重跑 `tools/gen_fonts.sh`（中文字形集从源码扫，字形集变化会重算）。

## 5. 组件解剖

**(a) KPI 卡**：标签在**数字上方**（13/文本3）；数字在下（30 或 22，文本1）；**单位行内且弱化**
（绝不另起一行）；底部基线放迷你趋势或 4px 容量条；卡内不放标题条、不放左侧色条。
层级靠"数字是卡内唯一 >14px 的元素"。

**(b) 清单行**（容器 / 卷 / 阵列 / 温度 / KV）：高 40（紧凑档 24/32）；行首 8px **实心色点**
（状态）或 16px 图标；名称 13/文本1；次行 11/文本4；行尾右对齐数值 13/文本1 或状态胶囊。
**行与行之间只有 1px `#F9FAFA12`，首行上方不画线。**

**(c) 状态胶囊**：高 24、圆角 4、**中性底 `#282B2F`** + 8px 实心色点 + 13px 文本2 标签。
**不用饱和底色**——这是 UniFi 最大的辨识点。

**(d) 容量条**：高 4（主容量条 8），圆角半高，轨道 `#34383D`；阈值
<60 绿 `#37BE5F` → 60–84 橙 `#E79913` → ≥85 红 `#EE6368`。60/85 两处画 1px 刻度线。

**(e) 时序图**：线宽 2，无点标记；面积 `#F9FAFA14`；**只画水平网格线**；轴标签 11/文本4；
图例在左上（8px 点 + 13px 标签）；**无边框、无坐标轴线、无竖网格**。

**(f) 导航项**：栏宽 76；每项 76×64：24px 图标居中 + 13px 中文标签；未选中图标/文字
`#B7BCC2`，选中图标与文字 `#F9FAFA` **并在左侧画 3×28 的 `#006EFF` 圆角指示条**；
hover/按下底 `#282B2F`。**栏右侧不画边框**，靠 `#1C1E21` 与 `#131416` 的色阶分离。

**(g) 页头**：高 56，背景即画布（不加底色），底部 1px `#F9FAFA12`。
左：24px 圆角 4 的品牌块（`#006EFF`）+ 19px 应用名；右：可信度胶囊 + Wi-Fi 信号条 + 时钟（22/文本2）。
页标题不放页头，放内容区的**页标题行**（19/600），右侧可放一行 11px 的统计说明。

## 6. 图标（5 个，实心几何，自绘）

UniFi 令牌包里没有区块图标，官方是**实心字形、圆角端点、单色**。本工程用矩形/圆角矩形拼：

| kind | 页 | 构成 |
| --- | --- | --- |
| `KK_ICON_OVERVIEW` | 总览 | 仪表：开口圆环（弧）+ 中心短指针 |
| `KK_ICON_STORAGE` | 存储 | 机架：3 条等高圆角横条（间距 3） |
| `KK_ICON_SERVICES` | 服务 | 容器箱：圆角方盒 + 上部一条底色横缝 |
| `KK_ICON_TRAFFIC` | 流量 | 上升柱：3 根不等高圆角竖条（5/11/17） |
| `KK_ICON_CONSOLE` | 系统 | 滑块：3 条圆角横线 + 各一枚偏心圆点 |

**同一栏内不得混用描边与实心，每个字形单色。**

## 7. 克制清单（可 grep 自查）

1. 任何地方**不用装饰性渐变**（v5 的 `KK_GRAD_*` 全部删除）。
2. **不用饱和状态色做背景**（`C_OK/C_WARN/C_DANGER` 只能出现在点、文字、进度条填充上）。
3. 卡片**圆角 ≤ 8**；只有胶囊/按钮允许 4，圆形允许半高。**不许再有 16**。
4. 边框只准 1px，且卡片**只在需要时**画 `#F9FAFA12`。
5. 内容区**不用阴影**。
6. 图表**无竖网格、无边框、无坐标轴**。
7. **不用大写标签、不用 letter-spacing、不用 700 字重**。
8. 禁用/陈旧**靠颜色变 `#737C87`/`#B7BCC2`，不用透明度渐隐**（v5 的 `#FFFFFF7A` 作废）。
9. 颜色语义排他：品牌蓝**只**表示可交互/选中。
10. 同一组件不得混用圆角与直角。

## 8. 信息架构：4 页 → 5 段

| v6 页 | id | 图标 | 回答什么问题 | 数据 |
| --- | --- | --- | --- | --- |
| 总览 | `P0Overview` | OVERVIEW | 现在好不好？ | 健康结论、CPU/内存/温度/运行时长、活动趋势、存储概览 |
| 存储 | `P1Storage` | STORAGE | 空间还剩多少、盘阵健不健康？ | 容量 Hero + 堆叠条 + ZFS、6 卷、4 阵列、4 磁盘 IO |
| **服务** | `P2Services` | SERVICES | 哪些服务在跑、有没有出事？ | 容器汇总 + 8 容器、告警清单 |
| **流量** | `P3Traffic` | TRAFFIC | 网卡在跑多少？ | 下行/上行主值、双轨趋势、峰值/延迟/累计 |
| **系统** | `P4Console` | CONSOLE | 采集链路和板子自己还正常吗？ | 运行时长/进程/堆/Wi-Fi、10 路温度、采集端点自检 |
| ~~网络~~ | → 流量 | | v5 的 P2Network 就是流量页，改名不改内容 |
| ~~系统~~ | → 服务 + 系统 | | v5 的 P3System 塞了 4 类东西，按 UniFi 拆成"客户端/控制台"两段 |

导航标签（`chrome.nav_*`）：总览 / 存储 / 服务 / 流量 / 系统。
翻页：5 个 nav 按钮 + 每页左右滑动（沿用 PRESS/RELEASE 差分，不用 LVGL gesture）。

**告警不再只挂底栏**：状态行常驻（32px，中性底 + 严重度点 + 一行原因 + 右侧轮询/年龄），
同时总览的健康横幅与服务的告警卡都完整列出。

## 10. 数据契约：不变的部分与变化的部分

* **不变**：Store 字段类型、绑定方向（OneWay）、所有格式化（printf）仍在 Controller、
  Binder 仍是唯一 LVGL 写者、`fnos_data.c` 与 NAS 侧 `fnos-agent` 一行不改。
* **id 重命名**（页面重排导致，同步改 `layout.json`/`bindings.json`/`Controller.c`）：
  * 容器与告警从 `Sy*` 迁到服务页 → `SvDot{i}` / `SvDock{i}` / `SvState{i}` / `SvAlertDot{i}` / `SvAlertLbl{i}`
  * 页面 Panel：`P2Network`→`P3Traffic`，`P3System`→`P4Console`，新增 `P2Services`
  * 导航：`NavOverview/NavStorage/NavServices/NavTraffic/NavConsole`
  * 事件：`OnNav{Services,Traffic,Console}Requested`、`On{Services,Traffic,Console}{Next,Prev}Requested`
* **颜色字符串**：Controller 里的 `C_OK/C_WARN/C_DANGER/C_SYNC/C_IDLE/C_HIDE` 全部按 §2 换值；
  可信度色从"白/半透明白"改成"文本1 / 文本3 / 文本4"（不用透明度）。
* **新增字段**：页标题行说明、KPI 副行、服务汇总、状态行——按 §9 清单补 `strings.json` 与 `bindings.json`。
