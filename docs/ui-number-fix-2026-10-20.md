# 数字跳变、过渡速度与圆心修复

用户在实机反馈数字跳变、渐变太快，以及 CPU／内存不同位数均偏离圆心。本次保留现有刷新优化与 Damped Springs 库。

## 原因与改动

- `100 → 9` 改变文本原点后，旧字形只有起点被转换，淡出终点仍属于旧坐标系。居中标签实测出现 17 px 多余横移。现在同时转换退场字形的起点与终点；重定向仍保留位置和速度。
- 原固定数字槽右对齐，与百分号一起居中；`9` 的可见字形实测向右偏 16 px。现在数字槽独立居中，按字体字形指标校正垂直中心，百分号位于下方圆环开口。
- 当前构建实际生效的原参数为 300 ms / 频率因子 8 / 阻尼比 0.85，其透明度 10%→90% 仅 100 ms。改为 600 ms / 8 / 1.0，实测主要渐变 252 ms；恢复 600 ms 共享数字呈现节拍。采集、历史、告警与切页时长不变。
- 同步 Kconfig、默认配置、头文件后备值及本机实际构建配置。判断生效值必须看构建缓存指向的配置和 `build/config/sdkconfig.h`，不能只看工程根目录遗留的 `sdkconfig`。

## 已验证

三个回归均先观察失败，再修复通过：

| 检查 | 修复前 | 修复后 |
| --- | --- | --- |
| 退场数字水平移动 | 17 px | 0 px |
| 单位数 `9` 的圆心水平偏差 | 16 px | 0 px |
| 透明度 10%→90% | 100 ms | 252 ms |

0、1、9、10、11、37、99、100 在两个圆环中都经过实际字形几何验证，中心误差不超过 1 px。缺失值、遮罩、快速重定向、重复目标和分配失败回归通过。

完整预览通过 169 帧与七套配色、四组硬件清单和分配失败恢复。六页数值动效包含 24 组数字／单位锚点；原生滑动、首次入页和重复目标均通过。ESP-IDF 5.5.3 / ESP32-P4 构建通过；静态栈检查全部入口在预算内，主任务 4432/16384 B，LVGL 4864/12288 B。

本地证据保存在 `tools/preview/out/number-fix-*`，旧固件与配置在 `number-fix-backup`，均不发布。主机逐帧和静态检查不代表真实屏幕动态流畅度或长期运行验收。

## 本次设备验证

已烧录 ESP32-P4 rev3.2，官方工具正常退出，bootloader、应用、分区表三段均通过写入摘要校验。应用 SHA-256 前缀为 `8c73fd3a6423`。烧录后捕获 30 秒串口，采集成功计数 30→150，失败始终为 0，未见 panic、栈保护、断言或 watchdog 标记。通用串口分析器将 `fail=0` 误归为错误，以上结论来自原始日志逐项核对。

使用当前 Android 相机取证并查看照片：CPU 单位数与内存两位数已居中，百分号在下方开口；画面有反光和透视。照片只能确认当前布局，连续动画的实屏顺滑程度仍保留用户观感验收。照片、原始日志、回滚文件和固件保持本地。

按 `review-animations` 审查了时长、原点、重复目标与重定向；600 ms 用于高频遥测的舒缓呈现，切页仍保持原有时长。代码与主机验证通过，未把静态照片当作动态验收通过。
