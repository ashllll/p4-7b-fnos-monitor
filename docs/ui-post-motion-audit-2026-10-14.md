## 已复现并修复

| 项 | 原问题 | 修复与回归 |
| --- | --- | --- |
| 1 | 温度模块过期时，系统摘要和温度大字仍使用实时色，部分数字仍启动动画 | 跟随 `temps` 模块新鲜度；旧值静态发布、降低强调，温度大字旁标旧值；不可读数据占位 |
| 2 | 存储旧值仍显示明亮容量、健康阵列色和百分比色 | 容量、条形、卷和阵列统一降级；不可读清单不显示保留字段，恢复后重建 |
| 3 | 网络采集无权限时，顶部仍显示保留速率或有效 0.0，且接口卡隐藏了失败原因 | 三个速率占位且单位清空，页面明确显示原因；旧速率降低强调；真实零值仍正常显示；HTTP 延迟独立处理 |
| 4 | 实时最热传感器被无关 CPU 模块失败污染为旧值 | 首页与体检共用最高读数选择，状态跟随获胜来源，同温度优先实时来源 |
| 5 | 系统温度旧值被数字节拍门延迟，同页行短暂显示不同代读数 | 静态发布当前值与摘要，再停止动画；回归覆盖闭门时 45.6 → 46.7 |
| 6 | 体检把显式通道的真实 0°C/负温判为缺失 | 使用存在性而非正数判断；CPU 旧协议的零缺失语义保留 |
| 7 | CPU 更热时，体检仍显示较冷的通道温度并宣称无超限 | 与首页共用最高值；CPU 85°C、通道 45.6°C 时体检显示 85°C、关注至少一路 |
| 8 | 实时 CPU 最高值让旧传感器的关注数量也显得实时 | 数量新鲜度独立于最高值；85°C 实时 CPU + 24 路 80°C 旧传感器显示“关注 24 路 · 旧值” |

这些断言进入正常预览验收的 `verify_module_freshness()`。缺陷修复前已实际观察失败，修复后通过。额外临时真实 LVGL 场景覆盖 −5°C、同值实时来源优先，以及不可读列表恢复；临时压力测试覆盖 8000 次快速数字重定向、100 次在飞删除、隐藏与禁用，未发现新增动画核心缺陷。
