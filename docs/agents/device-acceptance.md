# 实机验收的取景与降级

没有 `capture-board` 时，默认结论是**未执行**，不是通过。主机预览、固件截图和串口命令都不能替代物理屏幕与触摸证据。

## 主路径

物理屏幕验收使用 `capture-board`：`tools/page_shot.py` 负责取景，`bash tools/verify_all.sh --photo` 负责解码；取景结果仍需人工判断。触摸、滑动、动效切换等交互必须由人在板前完成。

## 没有 capture-board 时

| 证据 | 能证明 | 不能证明 |
| --- | --- | --- |
| 手机光学录像/照片 | 屏幕真实像素、页面内容、可见的触摸动作与响应 | 未拍到操作时不能证明触摸；静态照片不能证明时序 |
| 固件 `shot` / `tools/shot_pull.py` | 真实固件的 LVGL 渲染（512×300、2×2 降采样） | 物理屏幕、全分辨率字形、触摸、发布时序、动效 |
| 串口 `page`/`temp`/`shot detail` | 页面控制器、页面切换和覆盖层 | GT911/LVGL 指针层与真实触摸 |
| 主机预览 `tools/preview/run.sh` | 版面、字库、越界、压叠审计；fixture 状态 | 实机、真实数据、真实触摸 |

光学录像要保留文件、时间范围和操作说明；只截取“屏幕变了”的帧不足以证明是手指动作。串口打开可能复位板子，跨命令的页面/动效状态不能默认连续。

## 异常状态与动效

- `retained/stale/denied/error` 只有在自然发生或用户明确授权扰动时记录；为了验收去改 NAS、网络、配对或配置不属于授权范围。没有证据就写“未执行”。
- “完整/精简”动效开关只有物理路径：设置与诊断卡底部“动效”行；当前没有 CLI 切换。命令切页经过的是页面控制器，不是触摸，也不是动效开关。
- 不能把主机 fixture（`PREVIEW_*`）或合成手势台架写成实机结果；它们不是板子上的用户操作。

## 通过口径

烧录、启动、静态页面和自然数据恢复可以按实际证据记通过；触摸、滑动、动效切换、异常状态必须逐项写“通过 / 未执行”，不能合并成一句“验收完成”。
