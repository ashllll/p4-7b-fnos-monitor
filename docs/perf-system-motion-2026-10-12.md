# 2026-10-12 整机交互性能与动画优化

本轮先在开发工程实施与验证，再同步源码到独立发布工程，针对滑动、切页卡顿和跟手差。主要收益来自减少 LVGL 刷新中的重复布局，
并让数字动画在页面过渡时让出绘制资源。以下数值均为本轮同一台 ESP32-P4 7B 的实机台架结果。

## 改动

1. 存储与系统清单复用已完成的布局测量。缓存依据实际尺寸、换行高度、可见性、条目数量、
   视口及兄弟构件几何变化失效；数量不变的长名称、数值宽度变化仍能触发重排。
2. 普通标签在可配置的栈缓冲中格式化一次，减少临时堆分配和重复格式化。
   `CONFIG_FNOS_UI_TEXT_SCRATCH_BYTES` 默认 256，范围 64–1024；超长内容继续精确分配，
   不截断名称。分配失败保留原内容、显示内存不足提示，下一拍重试。
3. 配对状态未变时不重设整组导航样式；已关闭面板的重复关闭、空闲状态重复选择当前页不再同步刷新整页。
4. 切页准备时静态显示进入页的最新数字；过渡结束后，后续数据更新恢复数字滚动。禁用动效或数字不可见时，
   已有数字动画在下一次动画采样释放图层。保留原有页面弹簧曲线与快速反向连续性。

## 实机测量口径

- 两版均启用相同台架和临时分段计时；测量期间使用正常在线数据。
- 每版七轮：首轮预热舍弃，随后每个用例六次有效重复，顺序与 0–500 ms 抖动由相同种子生成。
- 用例覆盖六页的 idle、tap、swipe，共 18 种；每版 108 条有效记录、216 次手势。
- 每条 tap/swipe 记录须含三个按下、三个松开样本，且输入超时缺失计数 `misses=0`，否则整条不接受。
- 表中的 P50/P95 是六次运行各自 P50/P95 的中位数，没有把分位数当作原始帧样本合并。
- 首帧口径为 LVGL `RENDER_READY` 回执。输入经过真实 LVGL 读取定时器，但由台架合成；
  不包含电容触控控制器、I2C 读取和面板扫描的完整物理延迟。`misses=0` 也不能证明没有显示丢帧。

  存储容器尺寸变化从十二次降为零；覆盖长卷名、长容器名、长文本分配失败与恢复。
- 800×480、1024×600、1280×800 下通过清单回归；同一棵树改变视口高度并恢复时，列宽正确重排。
- 原生输入自动响应、短划取消、纵向滚动隔离、快速反向、重复目标和首次入页均通过；
  六页数字更新与部分缓冲渲染检查通过。已检查中间帧和终帧，内容保持不透明、终帧无残影。

## 复验入口

```bash
./idf.sh build
python3 tools/stack_check.py
bash tools/preview/run.sh out-system-motion
PREVIEW_MOTION=0,1,0 PREVIEW_MOTION_SCROLL=1 PREVIEW_MOTION_RESPONSIVENESS=1 \
  tools/preview/build/preview /tmp/fnos-motion-response
PREVIEW_MOTION=0,1,0 PREVIEW_MOTION_INPUT=api PREVIEW_MOTION_REPEAT_TARGET=1 \
  tools/preview/build/preview /tmp/fnos-motion-repeat
PREVIEW_MOTION=0,3,0 PREVIEW_MOTION_INPUT=api PREVIEW_MOTION_FIRST_ENTRY=1 \
  tools/preview/build/preview /tmp/fnos-motion-first
```

公开源码使用模板配置另行构建验证；本文实机数据对应本地开发固件，个人配置与二进制不随源码发布。
