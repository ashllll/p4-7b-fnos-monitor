# 总览：CUKTECH 遥测语法

本轮只改变总览页，使用 `cuktech-screen-ui` 的 system profile。真实框架是 C / LVGL 9.5，复用 ui_kit 原生构件和采样接口。

## 设计合同

- 目标：7 英寸 1024×600 横屏触摸仪表；同时验证 800×480 和 1280×800。典型桌面观看距离，沿用项目字体和夜间模式；实机拍摄结果见后续验证记录。
- 页面问题：NAS 当前是否健康，资源、流量、容量是否有压力？第一眼是健康结论；第二眼是四个固定对象区域，顺序 CPU、内存、网络、存储；第三眼是峰值、采样数、卷名及数据可信度。
- CPU / 内存：大数字百分比、270° 当前占用弧、独立折线趋势；统一 0–100% 量程。CPU 展示核数、负载与队列，内存展示已用/总容量及交换用量。
- 网络：下行在左，上行在右，复用网络详情页的同一批真实历史样本，两条线共用动态量程。颜色与详情页保持一致。吞吐采用 1024 换算 KB/s、MB/s、GB/s，单位与主数字分开。
- 存储：已用总量、可用/总容量、总占用条、各卷当前占用比较条。各卷沿用采集器稳定顺序，超过视口可手动滚动，保留协议支持的全部卷。容量是当前快照，不能误称趋势。
- 温度：最高读数与设备/通道身份在健康摘要右侧；完整传感器详情仍在温度页。不会创建未采集的温度历史。
- 首帧：等待数据、`--`、空轨道；没有成功快照时不会把默认零值显示成有效读数。实际首帧背光/flush 时序沿用原固件，本轮不改变显示驱动。
- 信任状态：离线保留最后快照并压暗数字与图形，网络明确“旧历史 · 暂停更新”；采集段明确读不到/拒绝/错误时显示无有效读数，stale/partial 显示旧值；温度、容器、阵列分别检查自身采集段；真实零值仍是有效测量。
- 历史：仅 CPU%、内存%、RX/TX 有真实历史。UI 每次增量读取只用一个游标，再分发给所有图，重复 tick 不制造新点；局部失效冻结该图，正常采集段继续推进；恢复插入一次显式断点，断点不代表精确停采时长。图中显示实际有效采样数；没有逐点时间戳，不绘制虚构的精确时间轴，也不把断线补成零。
- 视觉：沿用集中式颜色/字体/间距令牌，近黑层次、稳定身份色、稀疏参考线；禁止 RGB565 大面积渐变。颜色之外有数字、单位、状态词提供第二信号。
- 尺寸：两行原生 flex 各分配余量，卡片两列等宽；弧尺寸由字体行高和间距派生，曲线占剩余空间。长次要说明省略，卷比较区独立滚动，不缩小全屏字体。
- 动效：只有已有换页淡入、严重事件呼吸及容量条补间；曲线推进只由新采样驱动，无装饰性波形或自动切页。
- 字体/缓冲：复用已有 Inter/Noto Sans SC 4bpp 子集和原生 LVGL 栅格，不引入运行时缩放；历史数组和 UI 堆沿用项目 PSRAM 路径，绘制/DSI 缓冲与刷新方式不变。

## 验证与边界

主机原生渲染验证布局、字形、真实零样本、缺失、模块拒绝、旧值、采样游标和最大卷数。ESP-IDF 构建和静态栈分析验证可链接与已知调用链预算。

实现阶段仅完成主机与构建验证，随后按用户指令烧录并检查实屏，结果见下方记录。触摸滚动、快速重复点击、刷新流畅度仍需要直接操作与观察；主机截图与成功构建不能替代这些证据。

## 实现阶段结果（2026-10-07）

- 3 档尺寸原生预览；每档 73 张状态截图（原有 67 张，加 6 张总览边界图），共 219 张。字形、布局、控件重叠和各页面既有回归通过。
- 新增真实零历史、共享游标无重复消费、DOWN/UP 与详情页一致、局部失效与恢复断点、离线冻结、实际指针拖动到最大卷数最后一个完整行及容量条可见、无卷与 warming 清空验证。
- ESP-IDF 5.5.3 / esp32p4 rev3.x 构建通过；静态调用链下界：主任务 4992/16384 B，LVGL 任务 7456/12288 B，均在预算内。此项不替代运行时高水位与面板验收。
- DSH Desktop plugin preflight 已通过，但实际固件目录没有 live worker session；UI bootstrap 所需共享锁被其他任务持有，两次重试后停止。未获本轮 DSH 复核，已由本地独立代理完成定向源码检查，发现的局部 freshness 问题已修正。
- 未烧录、未提交、未推送；未修改私密配置、旧迁移工作或采集器协议。

预览图均为匿名 fixture 示例数据，不是当前实机或 NAS 状态。主图：`docs/evidence/overview-cuktech/overview-1024x600.png`。

## 烧录与实机验证（2026-10-07）

- 使用 embed-ai-tool 的 flash-idf helper，以 230400 波特率烧录，未擦除 NVS。产物为 ESP32-P4 revision 3.00–3.99，与本板 rev3.2 匹配；源文件、UI 对象、ELF、BIN 时间顺序已独立核对。
- BIN SHA256：`45dfa6f3aa3c6da058e89f41f5c750301f0c8a085327f65db6553c838f234527`。启动日志 ELF 哈希前缀 `4c72ff49b` 与本地 ELF 一致，运行镜像身份已确认。
- 使用 serial-monitor 的读取实现，在同一持续持有的串口会话中复位一次、记录启动、切页并拍摄。观察约 9 分钟，最后一条周期日志为 `ok=510 / fail=0`；只出现一次启动，未发现 panic、assert、watchdog、栈 canary 或 DMA 描述符分配失败。
- 周期日志内部 RAM 空闲约 203 KB、DMA 约 165 KB，PSRAM 约 27195 KB，在所观察样本中稳定；这不是长期泄漏或运行栈高水位的证明。
- 实际查看总览、存储、网络、系统、温度五页，共 9 张烧录后相机预览截图（含释放串口后复查）。总览四区、独立 CPU/内存曲线、网络双曲线、卷占用条未见可确认的重叠或裁切；总览另有独立代理视觉复核。
- 两张总览画面间隔约 82 秒，数字、曲线及成功计数有变化，与串口持续采集相互印证。温度页两张画面间隔约 222 秒，仍为设备折叠列表，温度和计数更新，未在这两次观察中出现自行展开或换页。
- 切页通过已有 `page 0–4` 串口入口，不能替代导航按键的实际触摸验证。手指展开/折叠、卷列表滑动到末行、重复点击配对与系统模块仍未获得本轮直接操作证据。
- 画面为固定手机机位的相机 App 预览截图，有斜拍、反光和相机 `1X`/白点叠层；可用于布局和可读文字检查，不能据此确认色彩准确度、面板闪烁或动画流畅度。
- 实机原图和原始串口日志仅保留本地，没有加入仓库或发布。验证结束后回到总览并释放串口；释放后重新查看相机画面，计数已继续到 `ok=597 / fail=0`，数字和曲线仍在变化，没有依赖串口监视器保持运行。没有提交或推送。
