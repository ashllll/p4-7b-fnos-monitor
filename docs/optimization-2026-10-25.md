# 历史质量与验证入口优化（2026-10-25）

本轮完成历史质量缺口、UI 非阻塞读取、共享主机检查、安装包身份生成与格式检查。已按先固件、后 NAS 的顺序完成 ESP32-P4 烧录和 FPK 1.2.10 部署，短时在线与管理页验证通过；72 小时实机长测仍未开始。

源码起点为 `6e851b6df0bbf18f9fd1e0da1ce5385ea4a058eb` 加任务开始前已有的 1.2.9 包、manifest、版本默认值和部署记录。原有修改保留，原始 1.2.9 产物另存于本地排除目录。本轮候选 FPK 为 1.2.10，大小和 SHA-256 的唯一记录见 [release.json](../nas/fpk/release.json)。

## 行为变化

1. NAS 的历史行保持 `[ts, cpu, mem, rx_kbs, tx_kbs, temp_max]`，每个失效指标写 JSON `null`；真实零值仍是 `0`。模块 `stale/partial/denied/missing/error/disabled` 都不能冒充本次有效采样，其他健康模块独立前进。没有模块元数据的旧采集器仍按原契约兼容。
2. 固件把 `null` 解析为该指标的 `NAN`，实时历史提交也使用模块质量。UI 按每个样本绘图，不再拿当前模块状态过滤整批历史，也不在恢复时另外造一个采样点。当前失效期间到达的有效旧历史仍可显示。
3. `fnos_data_get()` 和 `fnos_data_hist_read_ex()` 改为非阻塞取锁。锁忙时保留原快照、样本缓冲和游标，下一次刷新重试。没有重写历史合并事务或缩短生产者锁区；不能将这项改动表述为已经提升实机 FPS。
4. `verify_all.sh` 与 `test_report.sh` 共用 54 项主机检查清单。补入 MPT、指标质量、锁竞争、包身份核对；完整预览包含硬件矩阵、OOM、首次入页、重复目标和动效。共享清单缺失会明确失败，不会生成假通过报告。
5. `build.sh` 从实际 FPK 自动生成 `release.json` 和 README 校验块，核对包内 manifest、fnpack 追加的 app.tgz MD5，以及整包 SHA-256 和字节数。篡改、来源版本不符或 README 标记缺失会被拒绝。
6. 恢复格式告警并把类型／参数不匹配设为编译错误；`set_txt/set_num` 带 printf 属性。修复 RISC-V 的 `uint32_t/int32_t` 格式不匹配，扩大 Wi-Fi 状态文字和告警数量缓冲。配对文件的三处既有诊断截断仍保留告警，尚未调整其 112 字节显示契约。

旧固件不支持历史行中前四项为 `null`，会跳过含缺口的整行。部署时应配套更新固件和 FPK；本轮已先烧录固件，再将 NAS 从 1.2.9 升级到 1.2.10。

本轮逐项执行共享清单，首轮暴露的失败项在修复后分别重跑；没有把首轮失败计为通过，也没有声称两个顶层入口从头到尾均单次全绿。报告入口另有桩测试，避免覆盖历史报告或触发设备阶段。

本机默认 Python 为 3.15，既有 TLS 证书清理函数的 `finally` 内 `return` 会触发 SyntaxWarning。NAS 对应 Python 3.12 下开发模式 30 轮通过。本轮没有为了消除新版解释器警告改动证书替换事务。

构建技能助手在恢复缓存时先执行 `set-target` 并提前返回，没有真正构建；已从保留配置恢复，改用同一已验证工具链执行项目 `idf.sh -B build-ui-remediation build`。该失败未计为构建通过。

## 部署与短时实测

- ESP32-P4 rev3.2、32 MB Flash；ESP-IDF 5.5.5 烧录退出成功，bootloader、分区表和应用三段哈希校验通过。应用 7,154,816 字节，SHA-256 `412d1f74445061497be622f50b14f29d9aaa55a7d66106ef0f17f4b8b42e3407`。个人运行产物和日志仅保留本地。
- NAS 升级前保存应用私有数据及 1.2.9 回退包。升级后应用中心和服务均为 1.2.10；reader、Docker transport、server、collector 四份安装源码与候选逐字节匹配。设置、配对记录与 TLS 证书保持一致，服务 UID 非 0。
- 三次间隔 5 秒的状态请求均 HTTP 200，9 个模块均 `ok`，采样序号持续增加。升级前串口采样成功数 150→240、失败为 0；升级后的另一段 25 秒日志成功数 870→960，累计失败为 6 且采样期间未增加，未见 panic、assert、watchdog 或栈保护异常。两段之间包括服务升级窗口，未采集该窗口完整日志，不能据此精确归因全部 6 次失败。
- Android 相机实拍并人工查看首页：读数、趋势和导航可见，但存在反光、倾斜与边缘裁切；只作为局部显示证据，不代表全屏触控或长期稳定性验收。
- 管理页首次打开空白，浏览器记录显示 iframe 文档请求停在 `Fetch.requestPaused`；同一服务直接入口正常。结束浏览器调试附着后，原桌面内嵌窗口立即显示 1.2.10 并持续更新采样序号，未修改服务代码或降低鉴权。应区分浏览器调试会话挂起与应用自身页面故障。
- `tools/release_check.sh` 隔离本地配置后构建通过并恢复配置。当前本地头文件的四个字段均与模板一致，因此此检查有 0 个非模板真实值，不能声称完成了四项真实凭据对照。
