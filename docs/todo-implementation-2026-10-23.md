## 代码审核遗留（2026-11-03）

来源：[代码审核报告](code-audit-2026-11-03.md)第 3 节。共 12 条未处理，按报告分类原样记录；本轮只登记，不修。

### 要改界面或锁结构（3 条）

- **B32（P1）** `fnos_ui.c:101`、`:3151`、`:3200` — 配网 AP 只建 7 行，超过 7 个不显示、不提示、不可滚动；提示行「共 %d 个网络」用的是截断后的 n，数字本身是错的。未处理原因：UI 结构改动，需单独验证与预览/实机回归。
- **B23（P2）** `fnos_ui.c:5541` — 温度块扩容失败直接降到已建块数，少显示设备但温度页没有「还有 N 台未显示」说明。未处理原因：降级不记录被裁数量。
- **B27（P2）** `fnos_pair.c:901-905`、`:1111`、`:1088` — 配对落盘在状态锁内做 NVS 写（含证书 1–2 KB、两次 commit），期间 LVGL 在 `fnos_pair_view` 上无限等锁、poll 在 generation 上等锁，整帧停顿、遥测停拍。未处理原因：写 NVS 与发布状态共用一把锁（与 A05 同源）。

### 需要产品取舍（8 条）

- **B04（P2）** `nas_companion_server.py:916-923` — 令牌可作为 `?token=` 传入；原因为 curl 方便保留的回退。未处理原因：是否保留需拍板（Q2）。
- **B05（P3）** `fnos_net.c:504-509` 与 `:521` — `esp_wifi_set_config` 失败时，界面/状态里的 SSID 已切到新值且 `s_configured=true`，radio 仍在旧配置，重启后才一致；原因是先更新状态后调用 `set_config`。未处理原因：待确认状态更新顺序（Q3）。
- **B07（P2）** `nas/fpk/contract_check.py:208` — 字段改名可被裸赋值正则误认，契约检查假通过（如 `_volumes` 内局部 `pct`）；原因是第三路正则 `\bname\s*=` 收得过宽。未处理原因：改法涉及契约检查口径（Q7）。
- **B09（P2）** `cmd/main:213-220`、`cmd/upgrade_init:43`、`cmd/config_callback:19-23` — 服务已被 KILL/非 0 退出仍判 stop 失败，升级/改配置被误拒；原因是 stop 只看退出码，不区分「本来就没在跑」。未处理原因：需确认可接受的终态。
- **B12（P2）** `fnos_collector.py:795-797` — 负温与 0 °C 通道被当「无传感器」丢弃，且无上限校验；原因是 `c <= 0` 直接 continue。未处理原因：合法范围需产品给定。
- **B13（P2）** `nas_companion_server.py:971/991/1119/1211` — 500 回显异常类型与文本、404 回显请求路径；原因是错误响应直接拼内部信息。未处理原因：对外错误文案口径需拍板。
- **B14（P2）** `nas_companion_server.py:767` — 501 只发 `Connection: close` 头、不置 `close_connection`，未读 body 被当下一请求解析；原因是响应关闭策略与连接对象不一致。未处理原因：该分支是否保留需确认。
- **B21（P2）** `fnos_ui.c:3925-3929` — 温度页每帧对分组做 O(g²) 同名去重，且每组一次 `uk_alloc`；24 路通道即每 100 ms O(n²) 加 n 次分配，全在 LVGL 任务；原因是分组算法与显示名重建无缓存。未处理原因：缓存策略属行为取舍。

### 证据不足（1 条）

- **B28（未确认）** `fnos_net.c:570`、`:628`、`:685` — 若扫描被连接中止时 ESP-Hosted 不上报 `SCAN_DONE`，`s_scan_busy` 永远为真，后续扫描请求全被挡；原因是只有 SCAN_DONE / 启动失败清 busy，无超时兜底。未处理原因：需先取实机串口日志确认，确认后再加 10 s 超时。
