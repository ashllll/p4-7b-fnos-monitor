# 架构与接口草案

日期：2026-10-22 · 方向已确认，传输、部署与适配细节为 proposed。
关联：[ADR-0008](../adr/0008-michka-remote-display-direction.md)、[ADR-0009](../adr/0009-jpeg-remote-display-poc.md)、[ADR-0010](../adr/0010-fnos-michka-data-adapter.md)。

## 1. 模块与接口

| 模块 | 输入 | 输出 | 关键责任 |
| --- | --- | --- | --- |
| 现有NAS屏幕伴侣 | 操作系统只读来源 | 带来源状态的采集快照 | 保留完整实体、来源时间和权限状态 |
| fnOS适配器 | 经认证的采集快照 | michka快照、NAS扩展状态 | 单位转换、主机身份、旧值语义 |
| michka Hub | 标准指标及扩展 | 网页、SSE、历史 | 原版应用与可追溯补丁 |
| 专用浏览器 | michka页面、输入事件 | 1024×600画面 | 独立会话、字体、渲染健康 |
| 显示网关 | 浏览器画面、P4事件 | 二进制图像帧、状态与事件确认 | 背压、认证、会话生命周期 |
| P4客户端 | 完整图像帧、健康信息 | 显示结果与触摸事件 | 解码、缓冲所有权、本地恢复 |

浏览器渲染与NAS指标采集分开。网关不拥有NAS管理权限；网页不持有采集器秘密；P4不直接使用任意CDP命令。

## 2. 部署候选

第一阶段使用PC承担浏览器与网关，michka与浏览器同机，减少试验变量。最终优先评估常驻NAS运行，但必须验证依赖、CPU／内存、浏览器稳定性及部署隔离；在容器里直接读取的系统指标不当然等于宿主NAS指标。

现有采集服务独立运行。适配器通过其公开且经认证的遥测接口读取，不直接访问其私有配置文件来取得凭据。michka可关闭本机采集，避免把渲染电脑数据混进NAS页面。实际部署路径、端口、账户和证书在实施时确认，不写入真实值。

保持专用浏览器运行，不复用个人浏览器配置、Cookie或桌面。CDP仅本机访问；网关会话只能指向固定michka来源，不能让P4指定任意URL或脚本。

固定上游还包含设置、令牌读取与系统操作接口，不能把“使用原版网页”当作已满足只读边界。实施时须隔离采集器凭据与运行身份，对屏幕不需要的控制接口在服务边界明确拒绝；只隐藏按钮不足以完成 AT-12。

## 3. 图像传输草案

首版候选：Chromium CDP JPEG抓帧 → 网关二进制WebSocket → P4硬件JPEG解码 → RGB565全屏图像。该能力依据及限制见 [来源表](SOURCES.md)，不把实验性CDP能力作为稳定帧率承诺。

### 协商和消息

下面是待实现的逻辑合同，不是已经存在的API或冻结的二进制布局。

| 消息 | 必需信息 | 约束 |
| --- | --- | --- |
| hello／accept | 协议版本、设备能力、会话ID、视口、编码、帧上限 | 首版1024×600、DPR=1；不支持的版本显式拒绝 |
| frame | 会话、帧序号、尺寸、编码、长度、浏览器抓帧时刻与时钟域、有效载荷 | JPEG完整帧；头与实际长度一致；限制解码尺寸；抓帧时间不替代遥测来源时间 |
| frame_ack | 帧序号、接收／解码／提交状态及同侧时长 | 提交显示与已物理呈现区分；若可观测则单列呈现 |
| input | 会话、事件序号、触点ID、down/move/up/cancel、逻辑坐标 | 坐标受视口约束，按下／抬起不能被合并掉 |
| input_ack | 已处理事件序号与会话 | 只说明注入状态，不等于像素反馈已呈现 |
| health | 会话、浏览器健康、抓帧健康、最新帧ID | 不能只用TCP存活宣告页面仍在正常渲染 |
| error | 稳定错误码、可读原因、是否可重试 | 错误信息不得包含凭据或原始敏感响应 |

每个缓冲区和长度都先验证再分配／解码；无效帧不覆盖最后完整画面。像素数据不经JSON Base64传到P4。编码与采样格式先用真实抓帧验证，必要时由网关规范化；规范化成本计入性能。

### 背压

网关只保留最新待发帧，P4只保留最新待解码帧；使用确认／额度限制在途数据。已写入TCP发送缓冲的旧字节不能被应用逻辑撤回，所以同时限制socket积压。超过滞后预算时停止继续排队、报告状态，必要时重建会话。

图像与输入可以在同一连接分消息类型；网关调度优先处理输入与健康消息。若实测单连接造成排队阻塞，再拆独立输入连接，不预先引入更多通道。

## 4. 缓冲和显示所有权

1024×600×2=1,228,800字节／RGB565帧，约1.17MiB；两帧约2.34MiB。还要加面板／适配器缓冲、JPEG输入、TLS、SDIO、UI、任务栈与对齐。32MB PSRAM不是新模块可独占的预算。

候选生命周期：可写缓冲 → 解码中 → 待显示 → 显示消费中 → 释放。任何阶段只有一个所有者；网络任务不直接修改LVGL对象，DMA尚在读取的缓冲不可复用。

首版保留BSP／LVGL显示所有权，在LVGL线程切换全屏图像，叠加本地状态。不要让旧六页控制器与远程会话同时消费触摸。只有实测确认复制是主要瓶颈，才评估面板直接提交；届时重新评审VSYNC、缓冲同步和本地界面切换。

现有代码配置ROTATE_180，且记录了DOUBLE_DIRECT首帧锁等待与NONE模式旋转限制。PoC不能凭理论吞吐删除这些约束。

## 5. 触摸合同

统一使用1024×600逻辑坐标，验证物理屏四角与中心。图像旋转和触摸变换只各执行一次。首版不引入缩放／黑边，后续若加入必须显式定义变换。

连续移动可以合并到最新坐标，但保留事件序列的开始和结束。断线、超时、浏览器重启、本地恢复界面打开时产生cancel，清除活动触点。网关对重复序号幂等处理，对旧会话拒绝处理；不重放缓存的旧操作。

通过真实浏览器触摸事件验证michka行为，鼠标点击测试只作辅助。原版长按、拖动和滑动由网页处理，P4仅处理本地恢复入口，不能重复解释相同远程手势。

## 6. 连接与健康状态

| 状态 | 用户看到 | 允许操作／转移 |
| --- | --- | --- |
| 未配置 | 本地连接界面 | 配网、设置网关 |
| 连接中 | 等待与阶段提示 | 取消、进入本地设置 |
| 已连接 | 原版页面与必要本地入口 | 远程输入；异常进入过期 |
| 画面过期 | 最后完整画面加本地提示 | 停止远程输入，重连或本地恢复 |
| 重连中 | 重连状态，保留最后完整画面 | 退避尝试，新会话成功后恢复 |
| 认证失败 | 明确认证／信任错误 | 修复身份或信任，不高频重试 |

若2秒内既没有新有效帧，也没有能证明浏览器／抓帧仍健康的状态，显示过期。静态页面允许健康心跳维持状态，但单纯网关进程存活不足以证明渲染健康。故障注入必须覆盖“socket活着、浏览器卡住”。

画面新鲜度与采集段状态独立。渲染器画面不断刷新时，NAS快照仍可能是旧值；不能由图像序号重置NAS时间。

## 7. fnOS数据映射

| 源信息 | 标准michka映射／扩展 | 必须核对 |
| --- | --- | --- |
| CPU总占用、负载、uptime | Cpu、Load、Uptime | 采样窗口、首次样本、时间戳 |
| 每核CPU | 当前P4快照没有 | 空列表／不展示，不能平分总占用伪造 |
| 内存与Swap | Mem | used定义、MB/MiB实际口径 |
| 全部网口及累计量 | Net列表 | KB/s真实倍率、重置、接口身份 |
| 挂载卷容量 | Disks列表 | 卷不等于物理盘，名称完整 |
| 物理盘读写／延迟／SMART | NAS扩展 | 测量是否存在、SMART采集时间 |
| RAID健康／成员／维护动作 | NAS扩展 | 健康与动作分别表达，未知不等于健康 |
| 温度设备／通道 | Temps与扩展身份 | 同名不覆盖、0°C和负温合法 |
| 容器状态与资源 | Containers／扩展 | 稀疏更新、无权限、空列表区别 |
| ZFS、告警、遗漏数量 | NAS扩展 | 事件不等于历史、超预算明确提示 |
| 采集段状态与源时间 | 扩展与必要核心补丁 | 不刷新旧时间、不把缺失填0 |

标准接入候选是上游带令牌验证的 `/api/ingest`。实际认证格式与DTO以固定版本实现为准。新增NAS扩展通过受认证的同源接口提供给widget；选择反向代理或后端最小扩展前验证实际合同。

基础数字默认0及在线时间语义不能等价表达现有状态。对于来源失败，必须同时保留最后值、真实来源时间和非实时状态；若标准模型无法表达，应抑制错误入库并补充状态，必要时做最小核心补丁。错误情况展示与历史入库策略必须一起测试。

历史首版从接入时开始记录。现有平滑用于视觉呈现，不写回遥测、不当作真实历史或告警依据；迁移不承诺逐点复现旧LVGL曲线。

## 8. 上游维护和布局

上游固定提交独立管理。优先模板／widget，不把整个网页复制为另一套手工仿制。默认标准卡片由JS单行重排，双排布局需要核对重排和拖动逻辑，不能只覆盖CSS便宣布完成。

改动分为上游原件、衍生修改、新增独立模块、第三方依赖；每次升级比较接口、布局、状态及许可证。许可政策与归属清单见 [LICENSING](LICENSING.md)。

## 9. 观测与风险

记录捕获、发送、接收、解码、提交／呈现、输入确认；分开时钟域，禁止直接相减不同主机单调时钟。持续记录帧大小、丢弃、积压、重连、堆与任务高水位；输出汇总，不公开真实响应和凭据。

JPEG文本画质、CDP供帧、无线吞吐、全帧复制与浏览器资源是主要待测风险。首版使用全帧便于验证；是否进一步采用差分传输，只有性能报告证明必要才重开ADR。
