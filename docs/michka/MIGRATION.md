## 3. 去留决策

- **Go**：所有PoC强制项通过，有实际画面和测量证据；开始完整数据适配。
- **No-go**：画质不可读、输入错误、无法恢复、帧率或延迟未达标；保留证据并暂停功能扩张。
- 先分段定位抓帧、网络、解码、复制／上屏、输入瓶颈，做有依据的优化再复测。
- 若优化仍未达到目标，报告实际可用上限。不得静默改成LVGL仿制，也不得把15fps展示称为已达到25fps目标。
- 用户选择改变目标时，更新PRD／验收／相关ADR，记录旧目标和原因，重新执行相关验收。

## 5. 每阶段回退

| 阶段失败 | 回退动作 | 必须保留 |
| --- | --- | --- |
| 原版／网关试验 | 停止实验进程，恢复旧屏幕日常使用 | 上游版本、参数与失败报告 |
| P4候选固件 | 使用已核对的旧源码与本地配置恢复固件 | 原配置／NVS策略、原固件指纹；不能全片擦除代替回退 |
| 数据适配器 | 停止适配器，不卸载或修改原采集服务 | 原NAS配对和证书、适配日志汇总 |
| 模板／上游升级 | 恢复之前模板和固定上游版本 | 修改清单、配置与兼容的数据库备份 |
| 常驻服务 | 恢复之前服务版本和持久化状态 | 版本对应的配置／数据库备份与恢复记录 |

旧固件是否需要回刷取决于当时实验模式；不能把“计划有回退”写成“回退已经验证”。SQLite备份使用一致性备份或停服复制，不只拷贝正在写入的主文件。恢复凭据和证书不可公开。
