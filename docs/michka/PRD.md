# PRD：michka 原版远程触控状态屏

版本：0.1 · 日期：2026-10-22 · 状态：产品方向确认，细化要求作为实施验收基线。

## 1. 问题与目标

用户希望用 michka 的实际网页与交互替换当前显示体验，同时保留现有 P4 开发板。当前固件以 LVGL 原生绘制，michka 则需要 .NET 服务和浏览器，两者运行环境不同。产品选择外部渲染，P4 作为远程触控终端。

成功不是“截一张图显示在板上”，而是用户可以持续查看真实 NAS 状态，及时点击、拖动、滚动，并在故障时看懂原因、恢复连接。先证明实际画面链路可用，再扩展监控功能。

## 2. 用户与场景

| 用户／场景 | 用户要完成的事 | 产品必须提供 |
| --- | --- | --- |
| 桌面状态查看 | 抬眼了解 CPU、内存、吞吐、容量、温度 | 清晰数值、主机身份、可信状态 |
| 排查异常 | 找到具体磁盘、阵列、网口或温度通道 | 完整清单、详情、来源状态 |
| 日常触控 | 切换、长按、拖动、滚动 | 一致坐标、及时反馈、无残留按压 |
| 断网／远端故障 | 确认画面过期并恢复 | 本地提示、重连、独立恢复入口 |
| 后续维护 | 更新上游、追踪本地修改、回滚 | 固定版本、变更记录、许可清单、恢复方案 |

## 4. 主要用户流程

### 首次使用

1. P4 启动本地界面，完成网络配置。
2. 连接显示网关，完成独立身份和信任校验；不能把 NAS 采集凭据误当显示凭据。
3. 建立 1024×600 会话，显示明确的监控主机名称。
4. 首帧通过完整解码后替换连接页；等待遥测时显示等待状态，不显示虚假零值。
5. 点按、长按和滚动由原版 michka 执行，本地入口始终可达。

### 正常监控

首页展示 CPU、内存、网络、存储、温度。完整迁移阶段通过扩展查看阵列、SMART、磁盘读写、容器和告警。用户无需理解浏览器、编码和协议。渲染主机性能诊断仅进入设置／诊断页。

### 故障与恢复

画面链路失效时本地覆盖提示，最后一帧不再冒充实时；NAS采集失效而画面链路仍正常时，网页展示采集来源状态。重连后不重放断线期间的输入，认证失败提供修复路径。不能要求用户先操作已不可用的远端页面才能恢复。

### 布局调整

原版支持的卡片移动和设置优先保留。必须验证长按与页面滑动、纵向列表的冲突。新模板只改变布局，不让设备数量变成固定生产上限。

## 5. 信息与视觉要求

- 尊重 michka 原版风格，优先模板／widget 扩展；若核心修改不可避免，明确标为适配版。
- 只做当前横屏；不通过缩小所有文字把超宽仪表带硬塞入屏幕。
- 主要数值优先，单位稳定，长名称有完整阅读入口；告警不能只靠颜色区分。
- 中文字体必须在渲染主机可用；JPEG彩边、渐变色带要经过实屏验证。
- 本地连接／恢复界面与远端网页的输入归属清晰，不出现一触两用。
- P4自动背光可以继续本地控制；michka的远端系统屏幕操作不自动映射到NAS控制。
- 原版布局评估后，推荐候选为上排CPU／内存／网络、下排存储／温度；具体几何以实际模板渲染为准，不冻结未经验证的像素坐标。

## 7. 产品去留与开放问题

PoC必须同时满足帧率、反馈、画质和基本恢复要求。任何一项不满足都不能宣布“迁移成功”。只有通过后才扩大NAS扩展和常驻部署。

待PoC回答：当前无线环境带宽；抓帧稳定性；JPEG小字画质；P4复制／旋转成本；模板是否需要核心补丁；最终渲染部署在NAS还是常开PC。PC只用于试验不代表用户承诺长期保持PC开机。
