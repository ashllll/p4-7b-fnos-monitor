# 2026-10-23 对齐、动效与高 FPS 调查验证

本轮修复首页圆环和共享读数对齐，恢复完整平滑曲线，减少重复布局及绘制任务。**在线拖动仍约 20–26 FPS，没有达到稳定 60 FPS 或“丝滑”验收。** 本文归档实际保留的实现、测试证据及未通过的成熟方案对照，不把帧率上限当成实测结果。

## 范围与基线

- GitHub `main` 基线：`c3e1083c3fe134dcc57ac4c718a56db23de5f196`；本轮源码与文档在独立发布目录核验后一起提交，沿用已有历史。
- 目标为 Waveshare ESP32-P4-WIFI6-Touch-LCD-7B，1024×600 横屏、P4 rev3.x、当前 Slate 界面。
- 最终保留 ESP-IDF 5.5.3、LVGL 9.5.0、esp_lvgl_adapter 0.6.4、120 行 PARTIAL 和两个软件绘制线程。LVGL 将这两个线程归入同一个软件 draw unit，不能将 `units=1` 解释成一个线程。
- 开发目录的真实 Wi-Fi 配置与设备 NVS 已按用户更正恢复连接；发布只使用占位模板，不包含个人网络参数、接口响应、拍屏、串口日志或实机固件。
- 发布目录原有的远程显示迁移规划、README、术语和 ADR 工作单独保留，未混入本轮提交。

## 保留的改动

| 位置 | 改动与目的 |
| --- | --- |
| `fnos_ui.c` | 圆环数字独立以圆心为锚点，百分号放在下方开口；按字形计算纵向补偿。容量预留宽度，缺失容量提示独占读数行。 |
| `uk.c` / `uk.h` / `uk_theme.h` | 创建数字和单位时按字体基线差对齐，替换固定留白；不增加每帧布局。 |
| `uk.c` | 复用 D3 Basis 和 LVGL 原生 polyline，按系列计算坐标变换、滚动复用邻点、每批最多 64 个点。保留四分之一像素细分界限、全部源样本、缺口和隐藏序列；批次大小不限制历史或设备数量。切页中仍保留平滑曲线。 |
| `fnos_chart_math.cmake` | 构建时生成原生 `lv_draw_line.c` 修正版，只在最后扩张一次笔宽包围盒，避免多点循环累计膨胀；不改 managed dependency。上游语句变化时停止构建要求复核。 |
| `fnos_ui.c` | 网络清单复用现有几何指纹缓存，尺寸、可见性或数量变化才重排；目标页正文延后到落位立即刷新。 |
| `uk_number.c` / `fnos_data.c` | 保留本轮开始时已有的同文本短路及连续三次失败才判离线，避免重复布局和单次超时抖动；失败计数与原因仍更新。 |
| `Kconfig` / `sdkconfig.defaults` | 数字与仪表响应为 600 ms，两个软件线程写入默认配置；采集周期、真实更新发布策略不变，趋势上限仍为 60 FPS。已有 sdkconfig 需主动核对，默认值不会自动覆盖本地旧值。 |
| 主机预览与栈工具 | 增加圆心像素、28 组读数/单位、TB/零值/负数/缺失、原生折线范围、网络稳定刷新回归；主机 UI 编译单元固定每次运行的墙钟，设备时间不变；绘制回调纳入栈入口。 |

完整对齐证据见 [数值位置与基线修复](ui-alignment-2026-10-23.md)，优化过程与三轮对照见 [FPS 记录](ui-fps-2026-10-23.md)。本轮 UI 检查使用 `interface-design`，实现与发布复核按 `ponytail` / `ponytail-review`，固件构建按 `build-idf` 执行。

## 验证结果与边界

开发候选已完成以下检查；发布目录的独立复验另列于末节，避免把开发环境证据当成模板构建结果。

- 主机完整预览 131 张状态画面及 10 张刷新/对齐画面通过；字形、格式残留、标签溢出、父子越界、点击重叠、快照 ownership、空/紧凑/混合/密集清单及受控分配失败恢复通过。
- `0 / 9 / 37 / 99 / 100` 圆环最终像素横向误差不超过 1 px、纵向为 0 px；同行数字/单位基线差为 0 px。64 点批次保留缺口、隐藏序列和附着游标，180 点双曲线线任务由 358 降到 11。原生包围盒修正前后 131 张页面正文逐像素一致。
- 16 ms 虚拟采样的 390 帧往返/滚动/响应/重复目标、379 帧网络往返、163 帧首次系统入页通过。虚拟帧步长不是设备 FPS；本轮较早的 328 帧 ASan/UBSan 检查也通过，失败的缓存实验未保留。
- 设备正常固件构建及任务栈静态下界检查通过，LVGL 为 5120 / 12288 B；这不是包含所有间接调用与中断的精确峰值。`uk.c`、`uk_number.c` 和生成的折线副本 GCC analyzer 无诊断，UI 构建仍有既有的 `fmt_period` 未使用警告。
- 正常固件烧录后，bootloader、应用、分区表校验通过；六页经串口页号确认并查看新鲜拍屏。可见范围的圆环、容量、网络单位、温度和告警读数无明显错位；手机倾斜且右侧有裁切，尚不能声称整屏物理像素验收。

最终正常配置在线三次运行，以下是每次分位数的中位数；窗口平均值包含完整测量窗口，不能与 P50 倒数混用：

| 场景 | 帧间隔 P50 / P95（ms） | P50 倒数（FPS） | 窗口平均（FPS） |
| --- | --- | --- | --- |
| 首页持续刷新 | 16.576 / 25.803 | 60.3 | 54.2 |
| 网络持续刷新 | 18.000 / 48.086 | 55.6 | 45.2 |
| 首页拖动 | 49.010 / 56.585 | 20.4 | 24.9 |
| 网络拖动 | 44.872 / 52.676 | 22.3 | 25.7 |
| 系统拖动 | 38.650 / 45.984 | 25.9 | 35.7 |

18 次脚本手势无漏计；网络 tick P95 从约 64 ms 降至约 20 ms。每类指标最多保存 256 个样本，8 秒高帧率窗口不会保留所有帧间隔。测量的是软件渲染/刷新路径，60 Hz 面板扫描、软件完成计数和可见新画面数量不同；P50 倒数略高于 60 不代表面板超过 60 FPS。静态照片无法测动态 FPS。

## 成熟方案对照与回退

依据官方文档与源码逐项试验，完整来源、用例和原始分位数见 [官方显示栈调查](ui-fps-upstream-2026-10-23.md)。

| 方案 | 执行深度 | 结果与处理 |
| --- | --- | --- |
| LVGL 原生 PPA fill-only | 构建、烧录、同场景三次实测 | 无交互收益，恢复原配置；图片加速未验证。 |
| IDF 5.5.5 + adapter 0.7.3，原 PARTIAL | 构建、烧录、一次短测 | 无明确提升，最终回退；不能单凭这次试验否定新版的其他修复。 |
| 新栈 DOUBLE_DIRECT | 构建、烧录、一次短测 | 启动成功，但首页/网络拖动 P50 约 83 ms，淘汰。 |
| 新栈 TRIPLE_FULL | 仅构建 | 未烧录、未测量，没有性能结论。 |
| 官方热代码 IRAM + 64 行缓冲组合 | 构建、烧录、一次短测 | 无分配失败或防撕裂回退，但拖动 P50 约 48–57 ms，比原配置慢；恢复。不能单独归因于 IRAM。 |
| 早期同步页面快照 | 主机门禁与设备测试 | 首触约 105 ms、随后一次台架无响应，完整撤回。 |
| 后续官方 Snapshot + Image 集成 | 主机测试，未烧录 | 部分手势通过，完整状态与首次入页合同失败；未降低门禁，逐字恢复源码。 |
| DSH 辅助调查 | 两次启动尝试 | API 凭据缺失 / ACCOUNT_SIGN_IN_REQUIRED，未产出调查结果；独立哈希确认输入未改，不能计作完成独立评审。 |

上述依赖、BSP、入口及 sdkconfig 实验已恢复。恢复后的正常固件与试验前正常产物哈希一致；最后一次恢复短测六次拖动无漏计、无崩溃或缓冲回退标记，首页/网络/系统拖动 P50 为 47.159 / 42.317 / 38.256 ms。观察期采集累计 390 成功、2 失败；这是短测计数，不是零丢包或长期稳定性结论。

## 发布目录复验

发布验证以本次显式同步的 13 个源码/配置/测试文件和四份文档为范围。私有配置只用于本地无回显匹配，实际构建使用 `.example.h`，从 `sdkconfig.defaults` 生成新配置；验证结束恢复发布目录原有本地配置。发布不包含个人二进制或实机日志。

发布目录复验结果：

- 从默认配置生成的新模板构建通过，应用 7,087,056 B，SHA256 为 `2fbf0a4f9e345994e195de9d96a780d6da76b0eee491bbb58c9ce14e1efae35c`。该产物未烧录、未发布；设备测试对应开发候选，不对应这份占位固件。

- 完整预览 131 张状态 + 10 张刷新/对齐画面、四种硬件组合、快照及分配失败恢复通过；390 帧首页响应/往返、379 帧存储—网络往返、163 帧首次系统入页通过。
