# 拖动 FPS：原生分块与 LVGL 9.6 对照

日期：2026-10-24。目标板为 ESP32-P4 7B、1024×600。此前数字呈现节拍修正见[数字动效记录](ui-numeric-motion-2026-10-24.md)。本轮继续区分输入响应、渲染、flush、帧间隔和真实屏幕观感；不能用面板 60 Hz 或主机测试代替交互验收。

## 方案依据

参考用户提供的《ESP32 小屏动画公式手册》，采用其中先核算帧预算、连续目标保留位置和速度、数字呈现与采集分离的原则。当前已有 Ryan Juckett 闭式弹簧，能按实际时间步求值，不是可能随大帧距发散的显式欧拉积分。没有改写求解器或引入手册中的定点实现。

手册主要面向更小的屏幕，部分前提不能直接套用：本板走 MIPI DSI，不能使用 SPI 面板的传输预算；P4 具备单精度 FPU，不能据“ESP32 无 FPU”推断应替换现有浮点代码。[Espressif FPU 说明](https://developer.espressif.com/blog/2025/10/cores_with_fpu/)

当前耗时主要落在整页绘制。按顺序比较原生分块和官方稳定版软件 renderer；保留渐变、字体质量、圆环、曲线、真实采集、600 ms 数字呈现、180° 方向和触摸合同。未复做此前无效的渐变缓存、同步首触快照、IRAM 和 PPA fill 组合。

## 原生分块：4 比 2 更慢，已撤回

LVGL 9.5 已按两个 SW worker 默认设置两个 tile，本轮不是首次启用并行绘制。候选只通过 `lv_display_set_tile_cnt()` 将两个 tile 改为四个，复用原有 120 行像素缓冲、两个 worker 和三缓冲 PARTIAL。[LVGL 原生分块说明](https://lvgl.io/docs/open/9.5/main-modules/display/tiling.html)

每个页面各跑两轮、每轮两次脚本拖动。下表为每页两轮 P50 间隔的算术平均及其倒数，不是合并全部样本后的 P50，也不是光学帧率。

| 页面 | 原两 tile 间隔 / 倒数 | 四 tile 间隔 / 倒数 |
| --- | --- | --- |
| 首页 | 47.624 ms / 21.0 FPS | 55.364 ms / 18.1 FPS |
| 网络 | 44.034 ms / 22.7 FPS | 52.773 ms / 18.9 FPS |
| 系统 | 38.150 ms / 26.2 FPS | 47.344 ms / 21.1 FPS |

render P50 同时变长，更多 tile 没有改善当前负载。两组各十二次脚本拖动、零漏计，采集各 570 成功／0 失败，无故障或缓冲回退；四 tile 代码已逐字恢复，不进入交付源码。

## 官方稳定版软件绘制候选

固定 LVGL 9.6.0；上游 tag 对应 `80ca777e37a2b176770726a02e07a6fb79ef0b39`。官方重写了软件混合与变换路径，并优化未压缩字体解包。其 P4 “27→60 FPS”针对 rotated-ARGB 示例，不能视为本项目 RGB565 仪表页、适配器 180° 旋转或端到端拖动的预期收益。[固定上游变更记录](https://github.com/lvgl/lvgl/blob/80ca777e37a2b176770726a02e07a6fb79ef0b39/docs/src/changelog/CHANGELOG.mdx)

9.6.0 与旧 adapter 0.6.4 的第一次构建被其 FreeRTOS PSRAM 栈 hook 检查拒绝，没有绕过门禁。Espressif 的 0.7.2 已针对 9.6 的 `freertos/atomic.h` 修正；本次采用已有正式 0.7.3 和其要求的 IDF 5.5.5。[官方兼容修正](https://components.espressif.com/components/espressif/esp_lvgl_adapter/versions/0.7.2/changelog)

因此相对原板上版本，这是受支持的显示栈组合变化；没有配套 9.5／新栈对照前，不把性能差异单独归因于 LVGL。两个 tile、两个 worker、120 行 PARTIAL 和数字节拍保持一致。现有 chart 大坐标映射与 polyline 包围盒修正仍匹配 9.6 源码，继续保留。

主机完整状态／刷新、八套配色、动态清单和分配失败恢复通过；数字快速输入仍为 15 个采样、5 次目标变化、最短 600 ms。首次入页 71 帧、重复目标 96 帧、原生指针 151 帧、16 ms 步进指针 333 帧通过；六页 28 组数值／单位锚点通过。它们证明相应回归合同，不证明设备流畅。

候选构建及静态栈检查通过，ELF 为 `8aa7b4d1aae3dadfd39747fa694e49cfe7bb9e2365ba9733224c18c8fbbb0ab5`，三个烧录区域校验通过，未擦除 NVS。

以上为显示栈平移候选的阶段证据；最终裁剪揭示的实机结果、发布配置验证与尚存边界见下文。

## 显示栈对照结果

只升级受支持组合后，整页平移仍约 24.7／27.0／30.5 FPS。render P50 为 36.030／32.344／27.687 ms，变化有限；render-ready 到下一次 render-start 的间隙从约 10 ms 降到约 4 ms。不能把它描述为绘制速度翻倍。

同一新栈改为 FULL 时退步到约 10.1／12.1／12.1 FPS，已撤回。单 tile 诊断仅构建，未烧录或测量；最终仍用默认两个 tile。各候选的匿名逐轮时序见[对照 CSV](validation/2026-10-24-drag-reveal.csv)，不包含 NAS 响应或个人网络信息。

## 用户接受的原生裁剪揭示

用户选择优先顺滑，接受内容保持原位、揭示边界随手指移动。最终复用 LVGL 原生对象父子裁剪，每页永久保留一个透明容器；页面本身在动效期间保持完整视口尺寸，容器和子页反向移动，使内容的屏幕坐标不变。没有首触同步快照、像素缓存、自写绘制器或运行时换父分配。

几何修改和同步布局在同一 LVGL 线程、成对关闭／恢复失效计数之间完成。已有待绘脏区保留，只为前后边界经过的竖条追加失效；数字、图表等合法新脏区仍可增加帧成本。松手完成或取消后，恢复百分比尺寸并完整重绘视口，立即消费延迟的真实数据刷新。手势识别、纵向滚动隔离、速度连续的既有弹簧和数字 600 ms 共享呈现节拍均保留。

回归先在旧平移代码上因“双页内容静止”断言失败，再在揭示代码上通过。一次约 1% 宽度的小步只 flush 4,550／458,640 像素；原生输入查找验证裁剪外不能命中目标页、裁剪内可以命中。快速 API 反向额外发现页面根对象继承主题圆角，造成 12 个边角像素变化；明确让场景页背景为方角后，反向瞬间完整内容像素一致，卡片圆角保留。

首次拍屏还发现“空数据开机完成预热、NAS 随后上线”时，首入存储页先露出空态。新增相同启动顺序后，旧系统页回归因可见节点 35→182 而失败。修复预热失效依据：使用源快照清单数，而不是尚未创建的池对象数；入场前调用已有 `page_layout(to)`，仅刷新目标页的数据与布局。系统、存储首入各71帧回归转绿；没有恢复每个 tick 刷全六页。最终时序和拍屏均在此修复后重测。

## 最终实机时序

最终 ELF：`f1c616751ab2a0c5f0adc647583eac3daaf729cdfea45bf501bd220653c5895b`。三个烧录区域均校验通过，保留原 NVS 与 HTTPS 配对。复位启动回读同一 ELF 前缀后，先通过真实 NAS 在线门，再按相同 `swipe:<page>:450:2` 用例每页重复两轮，合计十二次拖动、零漏计。该计数是原生指针驱动注入，不代表真人触摸覆盖。

| 页面 | 旧平移 P50 间隔 | 最终揭示 P50 间隔 | 最终 P95 间隔 | 最终 render P50 | 按下到首帧 P50 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 首页 | 47.624 ms | 16.563 ms | 36.549 ms | 10.795 ms | 16.902 ms |
| 网络 | 44.034 ms | 16.562 ms | 34.209 ms | 10.856 ms | 13.942 ms |
| 系统 | 38.150 ms | 16.563 ms | 27.901 ms | 10.705 ms | 6.799 ms |

这些仍是两轮各自分位值的算术平均。P50 已接近面板标称 60 Hz 的周期；P95 仍约 28–37 ms，单次最大原始间隔约 151 ms，**不判定全程锁定 60 FPS 或尾帧问题清零**。计数器量的是 render-ready 帧间隔，不是光学呈现；其第一段间隔起点可能在按下门开启前，最大值不宜直接断言为持续拖动卡顿，后续仍需按阶段拆分长尾。均值 FPS 把停留、准备和收尾也算入，不能拿它冒充连续运动帧率。时序门和视觉门分别记录。

最终组合窗口有 870 次成功采集、0 失败，未见崩溃、栈保护、看门狗或绘制缓冲回退。十二次定量拖动之外，拍屏窗口另完成六次拖动、零漏计，P50 为 16.563 ms、P95 为 32.529 ms。

此前候选首次拍屏遇到 ADB screencap 20 秒超时，未把该次组合 runner 判通过；单独重试恢复。最终候选重新完成 home／network／home 三张 `capture-board` 图像、8 秒数字和10秒拖动预览录像，均保留本地并查看分析序列。手机录像轨约25 FPS，另有曝光、反光、斜拍和控件遮挡，不能据此证明光学60 FPS。

## 可复现检查与剩余边界

- ESP-IDF 5.5.5 配套 GCC 20260121 构建及静态栈检查通过；静态栈仅为下界。
- 当前代码在 `michka` 和 `cuktech-console` 各完整渲染 141 帧，覆盖字形、格式残留、标签／父子越界、可点重叠、对比度、八套配色、动态清单与受控分配失败恢复。
- 首次系统页 71 帧、重复目标 96 帧、16 ms 原生指针与纵向滚动 336 帧；返回终帧、反向瞬时内容、冻结历史与真实可见命中均检查。帧数是主机采样，不等于物理 FPS。
- 全 LVGL 与 UI 的 ASan／UBSan 指针与纵向滚动回归 336 帧通过，设置 `detect_leaks=0`，未宣称泄漏检测通过。数字快速流仍为 15 个输入、5 次目标变化、最短 600 ms；六页 28 组数字／单位锚点通过。
- 无个人配置的独立公开源码副本使用 `.example.h` 和同一锁文件重建通过；实机个人固件仅在本地。
- 第三目标仍沿用先完成当前公共目标再开始新转场的既有行为；途中转向第三页未新增专门回归。真实手指触控、完整取景、长测与故障注入继续按[当前待办](todo-implementation-2026-10-23.md)分别验收。

复现：激活对应 IDF 后执行 `./idf.sh build`，再执行 `FNOS_UI_DEVICE_CONFIG="$PWD/build/config/sdkconfig.h" bash tools/preview/run.sh`。原生交互与数字独立入口见[预览说明](../tools/preview/README.md)。实机使用 `tools/perf_bench.py` 重复相同页面用例，并保留在线门、固件身份与故障检查；不得直接把主机采样步长换算为设备性能。

本轮采用 `emil-design-eng` 的动效检查、原生 LVGL 裁剪和既有 Juckett 求解器。私人配置、固件、串口、上游调查与相机素材仅留本地，不随源码和文档发布。
