## 调查与修改

开始时的开发版已经包含 Slate 皮肤和 D3 Basis 曲线；未提交优化把趋势上限降到 24 FPS，切页期间关闭曲线细分，并把目标页刷新延后。实际本地配置还启用了两个软件绘制单元，与默认的一个不同。

本轮把平滑曲线改成固定大小的原生 polyline 批次，每条曲线每帧只计算一次坐标变换，再滚动复用相邻控制点。保留 D3 Basis、原来的四分之一像素细分误差界限、全部源数据和缺口。移除切页期间降为直线的开关。批次限制的是栈缓冲，历史与设备数量不受其限制。

趋势上限恢复 60 FPS。软件绘制线程经过设备 A/B 后保留两个，并同步默认配置；当前 LVGL 将多个软件线程归入同一个 SW draw unit，台架中的 `units=1` 不能当成软件线程数量。数字和仪表响应改为 600 ms，采样周期及每次真实更新的发布策略不变。目标页仍延后正文工作，但落位时立即补刷，避免等待下一次数据 tick。新增绘制回调进入静态栈检查的显式入口清单。

- `PREVIEW_CHART_MAP=1`：180 点、两条曲线的线任务由 358 降至 11；主机单帧探针由约 1320 μs 降到 570–633 μs。单次探针不能代表稳定设备加速比。缺口不连线、隐藏序列、游标、原始数据、长时间坐标重定位检查通过。
- 15 ms 虚拟调度检查：990 ms 内从 24 次趋势更新恢复至 59 次。这是调度回归，不能换算为 P4 实测 FPS。
- 默认主题与 `KK_PALETTE=michka` 的完整 `tools/preview/run.sh` 通过；包括状态画面、刷新工作量、快照 ownership、动态硬件清单和分配失败恢复。
- 16 ms 采样的 `PREVIEW_MOTION` 重复目标、响应预算、快速反向及首次系统页回归通过。真实 UI 代码的主机图像已经查看。
- ESP-IDF 5.5.3 / ESP32-P4 固件构建通过。GCC `-fanalyzer` 检查 `uk.c`、`uk_number.c` 无诊断；静态任务栈下界均在预算内，LVGL 入口为 5120 / 12288 B。构建原有的 `fmt_period` 未使用警告仍在。

## 设备分阶段实测

开始时的旧固件离线台架两轮拖动测得帧间隔 P50 30.119 ms、P95 32.914 ms，窗口平均 15.7 FPS。该窗口包含收尾，且测试时网络不可用，不能与在线持续曲线直接比较。照片只确认旧固件 Slate 页面可见。

用户已授权烧录、台架与拍屏。ESP-IDF 烧录完成并通过三个写入区域的校验。相同离线条件、450 px 两轮拖动的重复样本如下；表中是每次运行分位数的中位数，窗口包含收尾，不能把窗口平均 FPS 当作持续动画 FPS。

| 原生绘制配置 | 首页帧间隔 P50 / P95 | 按下至首帧 P50 |
| --- | --- | --- |
| 一个软件线程，3 次运行 | 34.726 / 38.044 ms | 48.299 ms |
| 两个软件线程，2 次运行 | 30.782 / 33.161 ms | 44.683 ms |

双线程的网络、系统页拖动帧间隔 P50 / P95 分别为 22.946 / 25.429 ms、20.912 / 22.929 ms，各两次运行，手势均未漏计。首页仍与旧基线接近，**没有达到高帧率目标**。离线静态页面约 5 次更新/秒是 200 ms 状态 tick，不代表正在运动的帧率。

最后恢复正常链接、重新从 ELF 生成固件并独立核对产物后，再次烧录并校验三个区域。最终固件分别在首页、网络、系统页各运行三次两轮拖动，共 18 次手势，均无漏计：帧间隔 P50 / P95 为 30.727 / 32.963 ms、22.844 / 25.944 ms、20.885 / 23.012 ms。串口观察未见崩溃标记，切回首页收到确认，并实际查看新鲜相机取景；本轮短测不等于长期稳定性验收。

还试验了两页 RGB565 原生快照缓存：主机布局、390 帧手势、220 帧首次入页、328 帧 ASan/UBSan 回归和静态栈检查通过，但实机首页首帧约 105 ms、帧间隔约 41–43 ms，随后一次连续台架串口无响应。该方案已完整撤回，未纳入稳定候选；这也说明主机通过不能代替设备验收。

已有高频探针仅临时参与诊断链接，未改变依赖源码。首页的两次采样中，每帧像素混合约 11.7 ms、文字绘制约 3.9 ms、flush 约 6.0 ms；文字包含其自身混合时间，这些数不能简单相加。诊断存在计时开销，不能与未开探针的绝对耗时比较；诊断链接随后撤销。

随后按用户更正更新本地 Wi-Fi 配置及设备 NVS，回读确认保存，设备获得 IP 并恢复 NAS 采集。在线短测累计观察到 870 次成功、5 次失败，未见崩溃标记；这是累计计数，不能解释为零丢包或长期稳定性验收。真实网络名称、密码、接口数据与照片只保存在本地。

同一正常固件在线运行三次八秒稳态、三次两轮拖动；表中是每次分位数的中位数，FPS 为 P50 帧间隔的倒数，并非窗口平均 FPS：

## 在线刷新阻塞修复

分段计时的 16 个样本确认：网口池重排中位 45.397 ms，KPI 更新 3.251 ms、网口文本 3.214 ms、KPI 布局 4.068 ms；诊断读取仅 0.027 ms，等锁假设不成立。网络正文及页面落位现在复用既有 `inventory_shape` 缓存，依据已解析的子项尺寸、可见性和数量判断重排，保留换行、设备增减及重新入页时的响应。

新增回归先复现稳定四拍网络行样式修改 8 次，修复后为 0。完整状态、空/紧凑/混合/密集清单、分配失败恢复以及物理网口/虚拟网口诊断回归通过。

设备同场景三次复测：网络页 tick P50/P95 从 58.358/64.115 ms 降到 14.491/19.802 ms，稳态帧间隔 P50/P95 从 24.250/108.267 ms 降到 19.924/46.891 ms；网络拖动 P50/P95 为 45.151/53.670 ms。18 次手势无漏计；短测未见崩溃，真实网络页与首页照片已查看。刷新长帧有改善，拖动帧率仍不足。

## 原生折线包围盒修复

当前 LVGL 9.5 的 `lv_draw_line` 在多点循环中反复给包围盒加笔宽，循环后又加一次；包围盒随点数增长，给独立绘制任务制造额外重叠。新增绘制任务范围回归先失败，修正后通过。保留末尾一次笔宽扩张，131 张页面正文与修正前逐像素一致，曲线数据、细分质量和笔画不变。

构建复用已有的项目局部 LVGL 集成：只生成并编译修正后的源文件副本，不改依赖目录；主机与设备共用相同修正。上游对应代码发生变化时构建停止，要求检查本地修正是否仍有必要。设备编译清单确认只编译一个修正副本，未重复编译原 `lv_draw_line.c`。

最终主机门禁通过：完整预览与硬件矩阵，390 帧响应/重复目标/反向，379 帧网络页往返，163 帧首次系统页入场；任务栈下界均在预算内，修正的原生折线文件 GCC analyzer 无诊断。


## 最终在线复测与当前限制

最终正常固件再次烧录并通过三个区域校验；同场景三次运行的分位数中位数如下。P50 对应 FPS 是帧间隔倒数，窗口平均 FPS 另列，不能互相替代。

| 页面/动作 | 帧间隔 P50 / P95 | P50 对应 FPS | 窗口平均 FPS |
| --- | --- | --- | --- |
| 首页持续刷新 | 16.576 / 25.803 ms | 60.3 | 54.2 |
| 网络持续刷新 | 18.000 / 48.086 ms | 55.6 | 45.2 |
| 首页拖动 | 49.010 / 56.585 ms | 20.4 | 24.9 |
| 网络拖动 | 44.872 / 52.676 ms | 22.3 | 25.7 |
| 系统拖动 | 38.650 / 45.984 ms | 25.9 | 35.7 |

网络页 tick P50/P95 为 14.549/20.772 ms。包围盒修正的拖动收益较小，不能解释为高帧率目标已实现；整页拖动绘制的中位耗时仍约 28–40 ms。台架每类指标最多保存 256 个样本，八秒稳态的高 FPS 场景并不保存全部帧，以上仍只是短测证据。

18 次手势无漏计，串口观察到累计 690 次采集成功、4 次失败，无崩溃标记或找不到 Wi-Fi 事件。最终网络页与首页均有串口页号确认，新鲜照片已经实际查看：首页 6、42 读数保持圆心锚点，网络速率切换为 MB/s 后单位位置正常；取景仍倾斜且右边缘有裁切，不能据此给出整屏像素级物理验收。设备最后留在首页。

当前结论：Wi-Fi 与在线采集恢复，对齐修复完成，网络页周期长帧缩短；**整页切换和拖动只有约 20–26 FPS，尚未达到用户要求的丝滑效果**。已保留正常候选及完整本地记录，未提交、推送或同步发布目录。
