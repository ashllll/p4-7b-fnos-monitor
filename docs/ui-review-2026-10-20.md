## 绘制工作量

相同健康数据、相同 LVGL 主机配置、局部绘制模式，每页连续四次推进 500ms。
统计 `flush_cb` 接收到的区域像素总数，允许重复区域计数；它是绘制工作量代理，不是 CPU 时间或实机帧率。

| 首页 | 改前 d923fb0 | 修复后 |
| --- | ---: | ---: |
| 四次稳定刷新像素 | 1,850,768 | 62,344 |
| 降幅 | — | 96.63% |

根因是 `overview_layout()` 重复设置相同的 flex-grow 和圆弧宽度，造成整行失效。
改用已有的差值样式更新函数，并缓存环内径对应的字体测量结果。
几何变化仍触发重新测量，动态数值及设备清单仍走原刷新路径。

默认 `run.sh` 的刷新回归现使用 `PREVIEW_PARTIAL=1`，要求首页四拍小于一整帧。
全帧模式原先每页都记录 2,457,600 像素，不能区分本问题。
其他页在本场景中的绘制量没有降低，未作全站性能提升声明。

静态栈是下界：工具列出的显式回调已计入，但不覆盖所有间接调用或中断嵌套。
Clang analyzer 对 `fnos_ui.c` 与 `ui_kit/uk.c` 保留三条诊断：
固定初始化的 `AGENT_KEY` 数组被推断为未初始化；`LV_MAX(1, uk_pool_cols())` 的重复调用被推断出零列；
含当前有效点的平滑窗口计数被推断为零。逐条核对完整数据路径和配置范围后，没有确认可达缺陷。
这不是“零静态告警”结论。通用 map 分析器对 P4 段汇总返回 0 B；ESP-IDF `size` 提供镜像大小，
但也提示 `sram_seg` 无法映射到芯片内存类型，因此不把其内存类型百分比视为完整物理 RAM 用量。
动态堆峰值需要新固件运行后另外采样。


helper 采用虚拟环境的 `bin/python3`，本次使用 `idf.sh` 时需把 `FNOS_IDF_PYTHON` 指向同一路径；
