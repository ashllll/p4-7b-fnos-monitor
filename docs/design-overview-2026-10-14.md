# fnOS Monitor 设计总览

本项目把飞牛 NAS 的负载、传输、容量、温度与异常变成一个可随时查看的桌面仪表。NAS 配套应用负责采集与设备授权，ESP32-P4 负责取数、保存快照和原生 LVGL 显示；用户先看总览，再进入专页、筛选与只读详情。

本文总结 **2026-10-14、源码基线 `cb26cda8169c68e5fb3fae684ff1262ac043d6a4`** 的已落地设计。它是现状总览，具体合同、参数和历史验证仍由各专项文档维护。本次整理更新本文与 README 入口，固件、NAS 业务代码、安装包及设备配置沿用原版。

## 1. 产品定位与设备合同

| 维度 | 当前设计 |
| --- | --- |
| 使用场景 | 桌面近距离观察 NAS，快速判断是否需要进一步检查 |
| 目标硬件 | Waveshare ESP32-P4-WIFI6-Touch-LCD-7B；ESP32-C6 通过 ESP-Hosted SDIO 提供无线连接 |
| 显示与输入 | 7 英寸、1024×600 横屏、MIPI-DSI、RGB565、GT911 触摸；底部导航、横向拖动、纵向清单滚动 |
| 软件栈 | ESP-IDF 5.5.3、ESP32-P4 rev3.x、LVGL 9.5；NAS 配套应用依赖 `python312` |
| 首要读数 | CPU、内存、网络收发、容量、最热来源；运行时长、服务与阵列状态补充上下文 |
| 可信度 | 对象身份、运行状态、采集新鲜度分别表达；真实零值、旧值与缺失各有语义 |
| 适配范围 | 当前只迭代这块板的横屏；设备数量、名称长度、清单增减与滚动可达持续自适应 |

显示运动独立于数据采样。增加视觉流畅度时复用显示层能力，采集频率由数据任务配置决定。参数、阈值、资源预算和主题集中配置，设备清单从实际数据推导。

## 2. 信息架构与阅读顺序

外壳由共享 `uk_shell` 建立：顶栏提供主机、连接与操作入口，全宽内容区承载当前页，底部六槽导航负责定位，事件底栏提供持续可达的状态入口。页面依次回答“总体如何、存储如何、网络如何、系统如何、哪里最热、需要处理什么”。

| 页面 | 第一眼答案 | 拆解与深入 | 交互与数据约束 |
| --- | --- | --- | --- |
| 总览 | 六张多功能状态卡 | CPU / 内存环表和趋势、运行时长与服务摘要、网络读数、容量、最热来源 | 维持稳定数字锚点；网速曲线集中在网络页 |
| 存储 | 已用、总量与可用容量 | 卷占用、阵列结构健康与维护进度、磁盘读写活动 | 按类别筛选；长名称、完整对象与详情可达 |
| 网络 | 上行、下行、双向合计与采集延迟 | 双线吞吐趋势、接口状态、链路速率与占用 | 采集延迟表示请求耗时，不能解释成 WAN ping；接口数量随数据变化 |
| 系统 | 系统摘要与容器运行情况 | 容器 CPU / 内存 / 重启次数、硬件温度 | 资源字段按实际采集能力显示；未启用、无权限与空清单分开 |
| 温度 | 最高可读温度及来源、近期趋势 | 按设备分组的温度条与全部传感器通道 | 多通道手动展开；展开选择与设备身份关联，设备清单可滚动 |
| 告警 | 当前事件的严重程度与原因 | 严重 / 警告 / 提示筛选；无事件时展示容量、温度、容器与采集体检 | 无事件不等于所有读数正常；当前事件清单也不等于事件历史 |

主值和图表优先，短标签说明对象，长解释放在详情与诊断。实体依稳定身份与顺序呈现；温度通道按设备／通道排序，同型号设备仍需保留各自身份。清单重排后，正在查看的对象不会因位置变化被替换。

### 从首次连接到日常查看

![首次连接：准备两端、核对指纹、确认结果与处理失败](diagrams/first-connection.svg)

Wi-Fi 扫描、密码键盘、六位配对码、证书核对、失败提示、详情和诊断共用主界面的字体、颜色、按钮与分组方式。用户在 NAS 管理页生成配对码，屏幕展示自行计算的证书指纹，人工逐段核对后建立信任。

详情保留打开时的快照，方便稳定阅读；返回列表后继续查看最新数据。诊断提供连接阶段、最近原因、数据年龄、来源状态及配网／配对入口。夜间显示保留信息层级，面板背光效果另做实屏验收。

## 3. 视觉系统：黑白为主，颜色承担明确角色

当前默认 `cuktech-console` 采用 CUKTECH ULTRA 参考方向。品牌参考提供仪表语法，色值是项目适配值；商品外壳、营销背景和参考图比例不进入界面。暖中性、UniFi 深色及黄绿方案保留为历史候选，当前视觉以 ULTRA 合同为准。

![总览：白色主读数、局部状态弧与稳定身份色趋势](images/ui-cuktech-ultra-2026-10-14/overview.png)

| 视觉角色 | 默认令牌 | 使用方式 |
| --- | --- | --- |
| 画布 / 卡片 / 浮层 | `#000000` / `#101010` / `#181818` | 用表面层级分组，保持整体克制 |
| 主读数 / 正文 / 辅助标签 | `#F8F8F8` / `#E0E0E0` / `#B8B8B8` | 主值最醒目，单位与解释退一级 |
| 选中、操作、提醒 | 蓝 `#75BFFF` | 控件形态和文字区分交互焦点与状态提醒 |
| CPU 历史 / 上行身份 | 橙 `#FFA23A` | 跨页保持指标身份 |
| 内存历史 / 下行身份 | 冰青 `#8ED7E5` | 与上行及 CPU 保持辨识 |
| 正常健康 / 严重异常 | 绿 `#8ED49C` / 朱红 `#FF5A45` | 配合事实文字与数值表达健康程度 |
| 当前占用率 | 默认 `<80%` 冰青、`80%–<90%` 蓝、`≥90%` 朱红 | 只改变局部弧／条；阈值来自 Kconfig |

颜色有三层职责：**身份说明“是谁”，状态说明“如何”，可信度说明“能否当作当前值”**。当前占用升高时，历史曲线保持身份色，主数字保持白色；旧值独立降低强调。颜色之外始终保留名称、数值、状态词或控件形态。

占用率判断集中在 `uk_pct_color(float)`，使用未取整的输入；负数与非有限值返回不可用色。主题默认值、预览初值与未知主题回退统一；已有 `sdkconfig` 保留用户设置，升级时需显式选择新主题。

### 字体与控件

关键数字采用原生尺寸生成的 Chakra Petch Bold 32 / 44 px、4 bpp，中文沿用 Noto Sans SC 字库。数值区预留稳定宽度，单位使用独立锚点，避免进位、位数或单位变化带动布局跳动。正文与辅助标签复用项目现有字库和字号层级。

卡片表达聚合值或真实对象；环表表达当前占用，条形表达比例与温度量程，趋势表达近期变化。筛选、按钮、键盘、输入框、对象行与浮层复用 `ui_kit`。修改共享构件时，六页、详情、诊断、配网和配对共同构成检查范围。

精确规则见 [ULTRA 设计](ui-cuktech-ultra-2026-10-14.md)与 [ADR-0004](adr/0004-identity-and-status-colors.md)。

## 4. 数据可信度与健康结论

连接可用、字段存在、模块实时是不同条件。界面先判断来源与读数的可用性，再格式化、决定是否动画，最后表达状态。

| 数据情形 | 呈现与行为 |
| --- | --- |
| 首次等待、从未成功 | 显示等待与占位，不从假零值开始扫入 |
| 当前有效测量 | 使用正常格式和单位；连续值可采用显示动效 |
| 有可读旧值、`stale/partial` | 保留可读部分并降低强调；立即发布语义变化，停止数值运动 |
| `denied/missing/error/disabled` 等不可读来源 | 显示占位和来源原因；权限不足或未启用不能格式化成健康零值 |
| 链路／请求失败 | 保留最后有效快照，显示连接原因与数据年龄 |
| 真实零值 | 按有效读数呈现；显式温度通道也允许 0°C 和负温度 |
| 旧协议 | 缺少模块状态字段时走兼容路径；旧协议 CPU 温度仍保留零表示缺失的语义 |
| 演示夹具 | 产品图使用匿名合成数据，图册与 manifest 明确来源 |

健康结论由共享摘要按当前快照推导，首页、事件底栏与告警页复用。严重度优先于事件原始顺序；没有告警事件仍需检查容量、温度、容器和采集状态。

最高温选择同时保留来源新鲜度，同温度优先实时来源。最高温读数与关注通道数量分别判断可信度：一个实时 CPU 读数不能把旧传感器统计变成实时。状态和阈值依据原始快照，显示中的滞后值只负责视觉呈现。

这些领域含义由 [GLOSSARY](../GLOSSARY.md) 与 [ADR-0003](adr/0003-module-freshness-and-reading-presence.md)约定。

## 5. 动效：采样、呈现节拍与运动各司其职

连续数字、环表、容量条与温度条使用共享临界阻尼；连续目标更新时保留当前显示位置和速度，直接重定向。相同目标保持现有运动，隐藏、缺失、旧值、离线、首次有效读数及单位／状态变化即时发布。

| 配置层 | 当前默认 | 含义 |
| --- | ---: | --- |
| 遥测请求周期 | 200 ms | 数据任务的请求节奏，包含请求与解析时间；慢周期不补发追赶突发 |
| UI 数据刷新下限 | 100 ms | 有效数据刷新周期取请求周期与该下限的较大值；导航另有显示节奏 |
| 数字共享呈现节拍 | 600 ms | 从真实更新中选择最新目标，控制数字变化密度 |
| 名义阻尼响应 | 450 ms、因子 8 | 静止阶跃响应为 `1-(1+ωt)exp(-ωt)`；中途更新保留速度 |
| 数字微位移 | 字体行高 4% | 固定锚点内的小幅变化；默认错峰与模糊均为 0 |
| 仪表落定 | 最迟两倍名义时长 | 默认 900 ms 内精确落定；合法量程始终限幅 |
| 减少动效 / 0 ms | 直接落定 | 保留可读目标与即时操作反馈 |

默认参数集中在 [Kconfig](../components/fnos_monitor/Kconfig)，表中数值是该基线默认，实际运行配置可不同。临界阻尼不保证任意初速度下都无过冲，反向允许短暂惯性，输出仍受合法范围约束。

共享指数查表约 2 KiB，减少逐帧指数计算；原生弧／条每显示单位使用 100 个内部刻度，避免整百分比跳格。可选动画分配失败时直接显示目标，删除对象时同步取消回调并释放运动状态。

历史使用真实样本与时间间隔，显示平滑和横向线性推进不回写采样值。历史回填、长间隔和切页忙碌时直接落定；来源失效时保留断流语义。输入优先于数据动效，拖动期间继续消费真实样本，较重的正文与对象池刷新延后补齐。

当前连续阻尼取代早期数字线性过渡方案；切页仍沿用原生跟手控制器。参数推导、回归范围与实屏限制见 [ADR-0002](adr/0002-continuous-telemetry-motion.md)和[动效记录](ui-ammeter-motion-2026-10-14.md)。

## 6. 清单自适应与资源降级

卷、阵列、磁盘、网口、容器、温度通道由快照实际条目数驱动。名称保留，列数、卡片高度和换行根据可用空间与文本测量推导；长清单通过滚动到达。筛选、增减、同型号设备、重排与温度展开均纳入主机矩阵。

资源策略以字节预算约束，而非设备数量上限：

| 配置 | 当前默认 | 超出或失败时 |
| --- | ---: | --- |
| `CONFIG_FNOS_STATUS_MAX_BYTES` | 262144 B | 拒绝超预算响应并保留最后有效快照，明确报错 |
| `CONFIG_FNOS_SNAPSHOT_MAX_BYTES` | 1048576 B | 拒绝无法完整保存的快照，避免静默少显示设备 |
| `CONFIG_FNOS_UI_LIST_MIN_WIDTH` | 260 px | 作为首选清单宽度，由实际空间与文字决定列数 |

旧版或主动限额的采集器可能提供不完整清单，固件需表达来源遗漏信息，不能补造设备。受控 UI 分配失败有可见提示和重试；真实 LVGL allocator 耗尽可能先触发断言，恢复能力仍需单独验证。

详见[硬件自适应审计](ui-hardware-adaptive-audit-2026-10-08.md)及[预览说明](../tools/preview/README.md)。夹具数量只描述验证组合。

## 7. 两端架构与模块职责

![运行数据流：NAS 采集、管理网关、HTTPS 取数与原生显示](diagrams/runtime-data-flow.svg)

| 模块 | 职责与接口约束 | 当前实现入口 |
| --- | --- | --- |
| NAS 采集与快照 | 从本机来源采样，发布读数、清单、模块状态和历史；同代编码结果供多个读取者复用 | [server](../nas/fpk/nasscreencompanion/app/server/) |
| NAS 管理与授权 | 配置、能力矩阵、诊断、证书及设备配对／撤销；管理网关与遥测端口职责分开 | [应用说明](../nas/fpk/README.md) |
| 网络与设备配对 | Wi-Fi、连接状态、配对步骤、证书确认和端点持久化 | [fnos_net.c](../components/fnos_monitor/fnos_net.c)、[fnos_pair.c](../components/fnos_monitor/fnos_pair.c) |
| 固件数据层 | 独立任务请求遥测、解析、发布快照及历史，处理失败与连接切换 | [fnos_data.c](../components/fnos_monitor/fnos_data.c) |
| 快照所有权 | 按需分配清单与字符串，引用计数控制生命周期，预算约束完整性 | [fnos_snapshot.c](../components/fnos_monitor/fnos_snapshot.c)、[数据合同](../components/fnos_monitor/fnos_data.h) |
| 页面与交互 | 读取快照、推导摘要、维护筛选／详情／切页，只有 LVGL 线程写 UI | [fnos_ui.c](../components/fnos_monitor/fnos_ui.c) |
| 共享原生构件 | 外壳、主题、数字、仪表、趋势、对象行、输入和动效生命周期 | [ui_kit](../components/fnos_monitor/ui_kit/) |
| 启动与平台适配 | NVS、网络、显示、主题、UI 重试、数据任务、背光与定时器 | [main.cpp](../main/main.cpp) |

UI 通过 `fnos_data_get` 读取快照，通过历史接口读取增量样本，界面内不发网络请求。快照句柄以 `{0}` 初始化；跨刷新保留时使用 `fnos_status_copy`，结束使用 `fnos_status_release`，避免裸结构体赋值造成借用字符串失效。取锁失败保持调用者原快照，历史游标还需处理 reset 与回填。

页面公共栏与正文分别刷新：`refresh_shell` 更新公共区域，`refresh_body` 使用明确目标页，导航准备通过 `refresh_page` 完成。共享健康摘要与温度摘要统一跨页含义；长诊断由冻结快照详情承载。模块接口保留现有调用方式，演示预览复用同一套 UI 实现与受控平台替身。

保留原生 LVGL 管线的理由是复用板级显示、触摸、布局与审计能力。历史 JSON/MVVM 管线已退出当前实现；该演进与共享构件决策见 [原生架构](ui-v12-lvgl-native.md)、[ADR-0001](adr/0001-native-instrument-ui.md)和[架构重构记录](architecture-refactor-2026-10-13.md)。

## 8. 遥测来源、通信与安全配对

| 数据 | 主要来源与可用条件 |
| --- | --- |
| CPU、负载、内存 | `/proc/stat`、`/proc/loadavg`、`/proc/meminfo` |
| 接口与流量 | `/proc/net/dev`、路由信息；各接口独立计算速率 |
| 卷、阵列、磁盘 IO | `/proc/mounts` 与 `statvfs`、`/proc/mdstat`、`/proc/diskstats` |
| 温度 | `/sys/class/hwmon/*/temp*_input`，由驱动和可读通道决定 |
| 容器 | 显式启用后，通过受限辅助进程查询固定 Docker GET；指标保留采集时间 |
| SMART | 可选 `smartctl`；取决于工具、设备与权限，跳过休眠盘 |

当前采集实现使用 Linux 本机来源。网络速率沿用项目 byte/s 系列格式；链路带宽使用 Mbps，采集延迟使用 ms，各自保持单位与含义。

配套应用默认 HTTPS 遥测端口为 **8798**；旧独立采集器与配置模板中的 **8799** 是另一入口，保存后的配对端点覆盖模板。开发板主动读取状态和历史，管理页通过飞牛应用网关打开。

首次明文引导只提供公开证书，信任由人工核对屏幕计算的 SHA-256 指纹建立。配对成功后保存端点、设备令牌与证书；日常遥测使用加密连接。证书改变需重新核对，撤销设备后其请求被拒绝，屏幕无需保存 NAS 管理员密码。

管理进程以普通包用户运行；生命周期脚本及独立 Docker 辅助进程承担各自所需权限。Docker Socket 权限很大，辅助进程仅接受受限读取指令并访问验证过的固定路径；管理服务不因此获得 Docker 控制权限。配置、证书保留与权限处理有独立回归，真实权限、掉电一致性及完整撤销路径仍按专项验收记录判断。

本节描述设计与已有实现，不构成新一轮安全审计。端点、安装维护和验证限制见 [NAS 应用说明](../nas/fpk/README.md)。

## 9. 显示性能、启动与工程取舍

显示沿用当前 BSP、180° framebuffer 旋转和 TRIPLE_PARTIAL 路径，触摸轴不额外镜像。该缓冲方式保留整帧搬运成本，局部控件变轻不能直接推导出同等比例的整帧性能提升。数据刷新、数字呈现与输入调度分别控制，性能结论需要真实板端测量。

当前启动顺序为 NVS → 网络 → 显示启动与亮度设置 → 选择主题 → UI 建树／重试 → 数据采集与定时器。主题在对象创建前选定，因为 LVGL 样式会复制颜色。当前背光设置发生在 UI 建树前；仅凭启动代码或构建结果，不能宣称所有复位路径都通过无花屏验收。

显示启动失败有明确日志；UI 锁或刷新定时器失败进入降级与重试路径。主任务栈预算为 16384 B，LVGL 为 12288 B；栈检查使用实际 ELF 的静态调用链下界，函数指针和中断组合仍有覆盖限制。大局部变量、构件增量和启动建树需同时核对栈与堆。

NAS Docker 指标的轮转、差值与缓存统一维护在 [docker_metrics.py.inc](../nas/docker_metrics.py.inc)，部署入口由同步检查保持一致；快照在采样发布时复制与编码一次，避免多个读取者反复复制完整清单。性能优化保留采集时间与旧值语义，相关历史测量见 [FPK 性能记录](fpk-performance-2026-10-12.md)。
