# 全界面尺寸与阅读顺序统一

## 范围与判断

针对当前 1024×600 横屏，沿用 ULTRA 黑底、蓝青焦点和朱红异常，重新检查总览、存储、网络、系统、温度、告警以及详情、诊断、配对、Wi-Fi 的尺寸规则。本次整理视觉层级，不改变采集频率、数字呈现节拍、历史或读数可信度。

设备监控围绕资源占用、容量余量、网络吞吐、传感器温度、服务状态与采集可信度展开。黑色画布、深灰表面、白色读数、蓝青身份与朱红异常来自现有仪表主题。保留圆环、历史曲线和容量条这一组仪表特征；不用额外大字制造每页独立焦点，不用按页面缩小卡片内边距，也不用固定窄名称列换取表面上的紧凑。

统一针对相同角色。主读数、实体读数、说明文字有明确层级；图表按可用空间伸展，长清单继续滚动，不强迫所有内容区具有相同高度。

## 共享尺度

| 角色 | 字号 / 尺寸 | 用途 |
| --- | --- | --- |
| 页面标题、详情身份 | CJK 20 | 页面识别和选中对象 |
| 卡片标题、正文、控件文字 | CJK 16 | 六页标题、设备名、操作 |
| 辅助文字、单位 | 12 | 时间轴、来源、说明、新鲜度 |
| 主指标 | 数字 32 | 首页读数、容量摘要、网络四项、最高温 |
| 实体读数 | 数字 20 | 设备温度、清单读数 |
| 卡片 / 内嵌面板内边距 | 8 | 统一 `UK_CARD_PAD` |
| 卡内内容间距 | 4 | 统一 `UK_CONTENT_GAP` |
| 卡片间距 / 清单间距 | 12 / 8 | 沿用共享间距阶梯 |
| 对象行内边距 | 水平 8、垂直 4 | 存储、网口、容器、温度 |
| 操作按钮、输入框、行触控下限 | 44 | 共用 `UK_ROW_H` |
| 常规进度条 / 摘要进度条 | 8 / 12 | 实体比较与整体容量分级 |

字体角色集中在 `ui_kit/uk_theme.h`，空间角色集中在 `ui_kit/uk.h`。尺寸由共享令牌和实际字体测量产生；设备数量、名称长度、卡片列数和滚动范围仍来自内容。

证书指纹和配对码保留各自的分组与宽度测量，这是可核对、安全输入的需求。完整诊断和告警文字可以换行，不能为了等高截断事实。

## 各界面拆解

| 界面 | 原有不一致 | 本次处理 |
| --- | --- | --- |
| 总览 | 容量读数为 20，其余主指标为 32；概览卡有单独紧凑样式 | 主读数统一 32、容量单位分离；九宫格直接继承共享卡片密度，保留等宽等高 |
| 存储 | 摘要标题 12，其他主指标标题 16；容量过长会单独缩字 | 标题 16，读数 32、单位 12，使用可换行空间；取消单页缩字 |
| 网络 | 同一排四项混用 44 / 32，卡片高度额外补空白 | 四项统一 32，卡片高度按共同内容测量，保留同排等宽等高 |
| 系统 | 卡片单独设 8 / 4，名称固定占三分之一 | 继承共享密度；名称和读数同一行，说明独立下一行 |
| 温度 | 最高温 44，通道名 12，设备条与其他清单不同 | 主温 32、通道名 16；实体进度条 8、对象内边距与清单一致 |
| 告警 | 摘要 20，而系统摘要 16；分级名称仅 12 | 摘要正文 16、分级标题 16，保留颜色与明确等级文字 |
| 设备详情 | 依赖共享卡片，需防止改密度后长名称溢出 | 继承统一卡片；身份 20、正文 16、返回按钮 44，保留完整内容 |
| 设置诊断 | 内嵌组与普通卡片使用不同内边距 | 内嵌面板与卡片共用空间令牌，保留键值列与滚动 |
| 配对 | 多张卡与数字键盘，需维持指纹可核对和操作可达 | 继承共用卡片与面板，保留码位、指纹分组、44 高操作 |
| Wi-Fi | 输入框 36 而“显示”按钮 44；功能键另用小字 | 输入框统一 44 并排显示，长输入保留全文并横向滚动；键盘操作字统一 16，五排键盘首屏完整可见 |

对象行统一阅读顺序：状态点 + 完整名称 + 右侧读数；下一行承载说明；最后是可选进度条。取消按容器宽度把名称固定分成三分之一的另一种布局。长名称换行，所有对象继续可达。

## 2026-10-16 圆环比例修正

CPU / 内存原圆环只按数字行高的两倍定径，64 px 外径与 12 px 环线使内圈仅 40 px，三位数读数拥挤。改为测量 `100` 的最大宽高，再加两侧环线和共享内侧间距：环线为 `UK_BAR_H / 2`，内侧间距为 `UK_S2`；当前字体得到 78 px 外径、4 px 环线、70 px 内径。数字与单位按照各自行高和 `UK_CONTENT_GAP` 组成整体居中的读数组。

增加三位数宽度、两侧留白及圆形比例断言，最高负载夹具显示真实 `100`。原实现会触发内圈间距断言；修复后 115 张预览、九宫格首屏边界、动态清单矩阵全部通过。已查看常规、零值、100% 渲染；两名独立审阅者无剩余发现。固件构建、七入口静态栈预算与目标 GCC 分析通过，应用分区仍有 26% 余量。本次仍未烧录。
