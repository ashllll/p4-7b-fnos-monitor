# 网络吞吐使用成熟 B 样条形成连续流水曲线

网络独占范围及单次平均已由 [ADR-0007](0007-all-trend-flow-smoothing.md) 替代；本记录的样条几何和原生绘制选择继续保留。

用户反馈网络吞吐尖角、凸起和凹陷过多，要求优先复用成熟动效方案。原实现的三点均值只降低数值波动，随后仍以直线拼接，不能消除切线断点。

采用 [D3 curveBasis](https://d3js.org/d3-shape/curve#curveBasis) 的三次 B 样条，仅在网络吞吐图启用。它是显示曲线的近似，不逐点穿过采样值；原始数据、当前吞吐、峰值、清单和告警继续读取原快照或隐藏原始序列。缺失值切断曲线，每段分别钳制端点，停止或隐藏后的历史保持原行为。这里扩展 ADR-0005 的曲线绘制，继续遵守 ADR-0003 的数据与显示分离。

对比过 [D3 curveMonotoneX](https://d3js.org/d3-shape/curve#curveMonotoneX)：适合需要穿过每个点且限制伪振荡的曲线；本次用户希望更柔和的流水形态，因此使用近似的 basis。也检查了 [LVGL 原生 CURVE](https://lvgl.io/docs/open/widgets/chart#chart-type)：当前工程需要开启额外矢量绘制后端，且其 9.5 实现按索引排横坐标，不能直接复用当前 XY 时间轴。

算法固定来自 d3-shape v3.2.0，仅做 C99 适配，完整 ISC 许可与源码摘要见 [第三方记录](../../components/fnos_monitor/ui_kit/third_party/README.md)。不增加运行时依赖。LVGL 继续拥有序列、裁剪、颜色、时间轴与软件绘线；通过其官方绘制任务事件，将网络序列的直线替换为样条折细后的原生多点线。细分误差按屏幕像素控制，栈缓冲分块，不设业务采样数量上限。P4 使用单精度硬件运算。

水平推进沿用现有线性、匀速时间轴；游标使用相同样条在可见右边界求位置。代价是增加本地绘制计算，须分别验证形状、原始统计、游标贴合、缺失段和设备运行，不能把数学光滑或主机虚拟帧率等同于实机流畅度。

同日根据实屏反馈，网络显示平均窗口独立配置为默认 9 点，复用已有移动平均，普通趋势仍默认 3 点。它进一步抑制密集短波动，接受约四个采样周期的趋势延迟；实时数字与峰值保持原始数据。窗口与缺失重置、阶跃响应及真实像素游标的验证见动效记录。
