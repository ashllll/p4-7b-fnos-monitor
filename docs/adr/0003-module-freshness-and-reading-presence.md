# 读数存在性、模块新鲜度和统计新鲜度分别判断

采集端在线只代表连接可用，不能推出网络、温度、存储等每个采集段都实时；零也不能统一作为缺失值。继续以快照中各模块的状态判断可读与实时：显式 `stale/partial` 保留旧值但降低强调、停止数值动画，`denied/missing/error` 等不可读状态使用占位和原因；无模块状态字段兼容旧协议。该策略替代只判断全局在线或把不可读字段格式化成健康零值的做法。

旧值及其他语义变化必须静态发布当前读数，再停止运动；仅停止动画不能发布被数字呈现节拍拦截的值。数值和单位同步更新，状态与告警基于原始快照，不根据滞后的绘制值判定。源采样、历史与显示运动各自保有语义，不能把界面插值写回真实数据。

首页和告警体检共用最高温选择，读数新鲜度跟随获胜来源，同温度优先实时来源；最高温和关注通道数量分别保留新鲜度，实时 CPU 不能把旧传感器统计升级为实时。显式温度通道允许真实 0°C 和负值，旧协议 CPU 温度仍保留零表示缺失的兼容语义。这样增加了状态组合及回归成本，但避免将旧值、缺失和真实零混为一谈。

判定及摘要实现位于 [`fnos_ui.c`](../../components/fnos_monitor/fnos_ui.c) 的 `overview_readable`、`overview_live` 与 `temperature_summary`；回归进入 [`preview.c`](../../tools/preview/preview.c) 的正常验收路径。已修复场景与验收限制见 [8 项缺陷复核](../ui-post-motion-audit-2026-10-14.md)。
