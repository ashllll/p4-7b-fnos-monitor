# 保留 fnOS 采集器，以适配器与 NAS 扩展接入 michka

现有采集快照包含阵列、SMART、磁盘活动、多温度通道、模块权限和新鲜度。直接替换成michka基础采集会造成能力或语义损失。因此建议保留现有只读采集器，由适配器向michka提供标准指标，NAS专属字段通过扩展及必要最小补丁表达。

## 取舍与替代方案

仅安装原版agent较容易开始，但不能据基础模型推断完整NAS能力等价。全面重写采集器会重复现有已验证的来源处理。适配器降低替换范围，但引入字段映射与上游升级合同，需要真实缺失状态和历史入库测试。

标准模型默认数字0不等于源数据有效；不能把不存在的每核CPU数据平分生成，也不能给旧值盖上当前时间。继续遵守[ADR-0003](0003-module-freshness-and-reading-presence.md)，画面流畅不改变任何采集段状态。

## 结果与接受条件

全设备清单动态保留，卷与物理盘区分，容器／SMART各自保留时间，单位按源定义转换。优先模板／widget和已有ingest；状态不可表达时允许可追溯的最小核心补丁。

[架构字段表](../michka/ARCHITECTURE.md)及AT-09～11通过后再接受实施方案。当前只确认保留信息的要求，适配器尚未实现；部署、认证格式和最终扩展接口仍要验证。
