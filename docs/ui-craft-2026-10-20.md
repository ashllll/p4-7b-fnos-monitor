# UI 优化 · 2026-10-20（oil-ui 存量优化：工艺 → 图标层 → 首页重排）

在不动品牌、六页 IA、字体与配色合同的前提下，对 1024×600 六页与详情/诊断/配对覆盖层做了三轮"存量优化"：先修工艺（九类问题、十余处改动），再补图标层（一套 18 个笔画图标接进卡头、行内与告警分级），最后按用户要求重排首页（hero 首行 + 2×2 状态瓦片）并把告警页改成事件流。每一处都有改前/改后的真实 LVGL 渲染帧作证。改动落在 `components/fnos_monitor/fnos_ui.c`、`components/fnos_monitor/ui_kit/uk.c`，以及同步了首页布局契约的 `tools/preview/preview.c`。

## 结论

| 项 | 结果 |
| --- | --- |
| 主流程渲染 | 124 帧（6 页 × 3 状态 + 硬件矩阵 + 夜间 + 覆盖层），字形/溢出/越界/点击重叠/格式残留/对比度/调色板全过 |
| 刷新回归 | 3 帧，稳定刷新、重复当前页导航、同名长名重排、过滤后清单重排与格式不截断 PASS |
| 预设 | 7 套主题全部渲染，127 帧无紫 |
| 数据层 | 快照解析、四组硬件清单（empty/compact/mixed/dense）、分配失败重试 PASS |
| 栈预算 | `tools/stack_check.py` 七个入口全 ✓（app_main 27%、lvgl_worker 41%、poll 74%） |
| 固件 | `./idf.sh build` 通过（ESP-IDF 5.5.3 / esp32p4 rev3.x） |
| 未做 | 本轮未烧录、未做触摸与长期刷新验收；结论只覆盖主机渲染 |

## 方法与证据

- 基线 `main` = `73d6626`，工作树干净。改动前先用同一预览程序渲染 124 帧：`tools/preview/out/ui-craft-before/`；改完渲染同帧集合：`tools/preview/out/ui-craft-final/`。
- 叠加对照图在 `tools/preview/out/ui-craft-final/compare/`：每张上=改前、下=改后；`temp.png` 是最热温度磁贴的 3× 局部对照。
- 目标屏只有 1024×600 横屏，RGB565 无渐变。只改现有构件与排版，不新增页面、字体或配色。

## 1. 读数是一个原子：单位跟着数字走

| 改前 | 改后 | 位置 |
| --- | --- | --- |
| 单位被推到卡片/列的最右缘，读成两个元素："12.2 …… MB/s"、"74.2 …… °C"、"17.8 …… TB"，网络四张 KPI 的 `MB/s`/`ms` 贴右缘 | 数值 label 不再 `width 0 + flex_grow 1`；单位紧跟数值，用 `pad_bottom` 压到数字基线 | `uk_kpi_create`（`components/fnos_monitor/ui_kit/uk.c:806`）、`build_p0` 网络吞吐（`fnos_ui.c:1465`）、`build_p0` 最热温度（`fnos_ui.c:1537`）、`build_p1` 三栏（`fnos_ui.c:1596`） |

根因是同一行里给数值加 `flex_grow 1` 想让它左对齐，结果把行内剩余空间全塞进数值与单位之间。`uk_row_create` 早就是"数值+单位紧邻右对齐"的正确范式，这次把同一范式推广到读数大字号的地方。

## 2. 首页最热温度磁贴

| 改前 | 改后 | 位置 |
| --- | --- | --- |
| 状态点压在 74.2 的基线上，像一颗孤立的句号；°C 在磁贴最右缘；脚注「最高 74.2°C · 容器不可用」既重复了上面的大字、又重复了右侧设备状态卡；迷你趋势被挤到贴着卡底的一条断线 | 状态点移到下一行与传感器名同排，标的是"那颗点属于这个传感器"；°C 紧跟数值；脚注收成异常态专线（温度旧值 / 高温 / 温度不可用 · 运行时长），正常态不出现；迷你趋势拿回高度，能看到起伏 | `build_p0`（`fnos_ui.c:1537-1556`）、`refresh_body`（`fnos_ui.c:4654-4666`） |

离线分支单独 `show(overview_note, true)`：离线文案不能被"正常态收口"规则吞掉。温度旧值仍由既有回归 `preview.c:2215` 断言。

## 3. 网络页 Y 轴刻度

刻度标签一直建在 38px 的左槽里，但图表创建时是 100% 宽，把槽压成 0 —— 渲染里只剩一条从卡片左缘起画的曲线。改成图表 `width 0 + grow` 后刻度出现；刻度色从 T4 提到 T3、右对齐、右留 4px，标签是"数字 + 竖排的三档"，不再贴曲线。位置 `build_p2`（`fnos_ui.c:1663-1685`）。

## 4. 存储页三张清单卡

| 改前 | 改后 | 位置 |
| --- | --- | --- |
| 列宽下限 390（`UK_ENTITY_MIN_WIDTH`）→ 1008 宽只放得下 2 列，第三张"磁盘活动"换行落到首屏之下：页面上只剩存储卷与阵列健康两张各约 498 px 的卡，磁盘活动整张消失 | 列宽下限参数化：存储页传 320（3 × 320 + 2 × 8 ≤ 1008），三张卡一行；系统页仍传 390，保持两卡半宽 | `inventory_sections_layout` / `inventory_sections`（`fnos_ui.c:3893`、`4032`）、`storage_layout`（`fnos_ui.c:4079`） |

## 5. 顶栏「设置」不再随页横跳

改前 `motion_snap` 与 `fnos_ui_set_page` 各有一句 `show(diagnostics_button, page == 3)`：构建时可见，一旦切页就只在系统页露面。于是同一个入口在 p0 有、p5 没有（改前对照图 `p5.png` 上排可直接看到），用户会以为功能时有时无。顶栏是设备外壳，不随页面增减按钮——改为常驻（`fnos_ui.c:1009-1018`，删除两处 `show`）。

## 6. 详情侧栏不再半盖底导航

改前蒙层是 1024×600 的屏幕子级，侧栏面板一路铺到底：面板右半压住导航，`返回列表` 按钮（y 542–581）正好落在最常用的一排导航键上。改后蒙层仍铺满全屏（模态、点外部关闭），但用蒙层自身的 pad 把面板收进内容区：`pad_top = UK_HEAD_H + UK_S2`（52）、`pad_bottom = UK_DOCK_H`（56），面板为 8..1016 × 52..544，导航完整可见但被压暗且不可点（模态语义）。位置 `entity_detail_build`（`fnos_ui.c:1370-1375`）。

## 7. 告警页：第四组不再落到折线以下

| 改前 | 改后 | 位置 |
| --- | --- | --- |
| 三个分级组各自预留 96 px（"两条消息"的下限）。真实分布是 1/2/1 条，于是严重组凭空多出 44 px 死区，提示组被挤到 544 以下，首屏看不到任何提示级事件 | 组列按实际条数取高（min_height 0），整个卡体本来就可滚动，不需要每组自留空位；组头加 `pad_top 12`，让组名离上一组更远、离自己的条目更近 | `build_p5`（`fnos_ui.c:2169`、`2184`） |

## 8. 过滤空态垂直居中

过滤后没有条目时，卡片已经吃满页高，单行「此等级暂无事件 · 选择全部查看」却贴顶，下面约 300 px 空白，读起来像"这页没画完"。改为：只有空态盒单独可见时把卡体主轴居中；有条目时回到 START（居中会把首条推出滚动区）。位置 `alert_health_sync`（`fnos_ui.c:4478-4485`）。

## 9. 行容器的假滚动条

行容器（`uk_row_box`）是布局条，不是滚动面。内容比容器多 1 px 时 LVGL 就会沿右缘画一条 3 px 滚动条：网络页图表右侧那条莫名其妙的浅竖线、卡片内缘的发丝线都是它。现统一 `LV_SCROLLBAR_MODE_OFF`（`uk.c:179-182`）。真正的清单池仍保留滚动条。

## 10. 图标层：图形先说明"这是什么"

第一轮改完，用户反馈"看起来没啥变化"，并要求**图标/图形承载信息优先**。于是给全站补了一层图标：不是贴图，而是沿用导航图标的 24 单位笔画画布（`NAV_LINE / NAV_RECT / NAV_ARC`），按尺寸缩放，RGB565 下没有渐变也能画清楚。

| 位置 | 图标 | 语义 |
| --- | --- | --- |
| 页面图标（原有 6 个） | 仪表弧 / 硬盘 / 节点 / 芯片 / 温度计 / 三角 | 六个页面身份 |
| 卡头 20 px | `ICON_CPU` / `ICON_MEM` | 首页 CPU、内存卡；色取该序列色（橙 / 青），图标与趋势线同色 |
| 卡头 20 px | `ICON_TREND` | 两张首页趋势卡、网络吞吐、温度趋势 |
| 卡头 20 px | `ICON_SERVER` / `ICON_CLOCK` / `ICON_BOX` / `ICON_LAYERS` | 设备状态、运行时长、容器、阵列 |
| 卡头 20 px | `ICON_RING` / 存储页图标 / 网络页图标 / 温度页图标 | 卷占用、存储卷、磁盘活动、网口与接口、硬件温度、设备温度 |
| 行内 14 px | `ICON_DOWN` / `ICON_UP` | 首页网络吞吐的"↓ 下行 / ↑ 上行"，网络页网口行的收/发 |

实现要点：

- `card_head_icon(card, kind, color)` 把图标作为卡的浮动子对象（`LV_OBJ_FLAG_IGNORE_LAYOUT` + `LV_ALIGN_TOP_LEFT 2,2`），再给头行 `pad_left = 20 + 8`。**不能**把它插进头行：`uk_card_title` / `uk_card_note` 的契约是"头行第 0、1 个子对象"，插一个进去会让刷新把标题当 note 清空（本轮真踩到：五张卡标题整行消失）。
- 图标对齐的是卡的内容区，所以卡头图标列与行内图标列共用同一条左缘；标题、数值、单位仍按原有字体角色，不新增字号。
- 小尺寸描边有下限：`width = max(2, width * size / 24)`，14 px 的行内图标不会细到发灰。
- 告警页卡头**没有**再放三角：页面标题已经扛着同一个三角，30 px 内重复一次只会稀释它。

## 11. 首页重排：hero 首行 + 2×2 状态瓦片

用户看完工艺+图标两轮后的原话是"我看起来咋没有啥变化呢 首页更多优化接受大概 但是图标信息呈现优先"，随后批准了三件事（"1 2 3 都要"）。这一节全部是结构变化，不是微调。

- **行高改成三段固定预算**（`overview_layout()`）：hero 213 / 趋势带 113 / 指标带 126（合计 452 + 2×12 = 476，正好铺满内容区）。此前是三行均分，第三行最矮；现在首行拿去做焦点。
- **环表 144 px、环内读数 44 px 且数字与 `%` 同行**：环径 = 行高 − 69（实测卡的 chrome 是 49 px，用 62 会溢出 meta 7 px），读数装进 `reading` 行（`uk_row_box` + `SIZE_CONTENT` + 居中对齐），单位用 `pad_bottom UK_UNIT_BASELINE` 贴基线。`overview_resource_t` 新增 `metric` 指针，布局时按环径重设。
- **设备状态卡改 2×2 图标瓦片**：每格 = 第一行 14 px 图标 + 12 px 标签、第二行 32 px 读数；状态并进标签（"容器 · 未启用"、"阵列 · 有降级"、"磁盘 · 1 个异常"），异常时读数染朱红。瓦片 49% 宽、`pad 6`、S2 底、`radius 4`；高度在布局里按 `max(76, (hero-53)/2)` 撑开（内容够 67，不撑时两行只占 139、卡底留一条空带），内容垂直居中。
- **磁盘瓦片的数字是磁盘总数，异常块数写进标签**：否则"磁盘 4 · SMART 异常"会被读成"4 块坏盘"。
- **指标带改成 4 张卡、网络卡双宽**（2:1:1:1）：网络卡两列"数值 + 单位"各要 ~150 px，均分 246 会触发审计 `inline metric overflow`（"0.003"+MB/s = 126 > 107）。
- **两张趋势卡改成纯趋势带**：不再建 12 px 的 `context` 行（图表自带 `min_height` 2×NUM32 行高 ≈95，会撑破 113 的行），改为 `r->context = NULL`，卡头 note 保留"峰 51%"。

## 12. 告警页改成事件流

- 一条告警一行：**分级图标（16 px，三角/菱形/圆圈 i）+ 正文（16 px，可换行）+ 右侧分级标签**（严重/警告/提示），行间 1 px 分隔线。
- 三个组头、组列与"1 条"计数全部删掉：分组信息已经由图标形状、标签文字和颜色三重编码给出，摘要条仍保留"严重 1 · 警告 2 · 提示 1"。
- **数据层没有时间戳**（`fnos_alert_t` 只有 `lv` 与 `m`），所以右侧给的是分级标签而不是时间；时间要去采集端加字段，本轮不编。
- 图标形状运行时切换靠 `nav_icon_set_kind()`：`nav_icon_draw` 先读 `lv_obj_get_user_data`，没有再退回回调参数；图标 box 在创建时就写入 user_data。
- 空态盒、2×2 体检瓦片、过滤胶囊都保留；空态单独出现时卡体 `flex_main_place = CENTER`。

## 13. 温度磁贴的三态互斥

一张 201 px 宽的磁贴同时只讲一件事：正常态给迷你趋势；短说明（"高温"/"温度旧值"）与传感器名共存；长说明（离线原因、"温度不可用 · 运行 2 天 07 小时"）占两行、传感器名整行让位。实现是 `home_temp_note` / `home_temp_long` 两个局部量 + `overview_note` 高度在两行/一行间切换。**不这么收口就会踩两条审计**：note 换行时把迷你趋势顶出卡体（child out of parent），以及 `verify_reasons` 断言"每条连接失败原因都要能在屏上读到全文"（DOTS 截断会让五条原因找不到）。

## 14. 环与读数的比例：笔画、字号、刻度槽都跟着尺寸走

用户反馈"状态圆环太细 比例不和谐"，并要求字体与图表有自适应能力。这一节把三处硬编码换成比例规则：

- **环笔画 = 直径的 7%，下限 6px**（`ring_stroke()`）：144 的环从 4px 变为 10px；96 的小环自动退到 6px。创建时直径与笔画互相依赖（笔画取决于直径、直径又要把笔画算进外径），用一次迭代收敛；布局阶段拿到最终环径后再落一次，保证不会"环放大了、笔画没跟上"。轨道与指示弧同宽，并都改成圆头——10px 的平头会像被裁断。
- **读数按位数选遮罩、按环内径选字号**：`ring_reading_fit()` 用 `"100 %"` 的实测宽与环内径比较，放得下用 44，放不下退 32；遮罩分别按 1/2/3 位数字量宽，刷新时按当前位数取用。因此 `37%` 不再常驻一段为 `100` 预留的空隙，`100%` 也不会被挤成两行。**遮罩宽度只能由刷新落**：布局阶段只知道环径、不知道当前是几位数，早先按两位写死会把正在显示的 `100` 折行（本机实测踩到）。
- **网络 Y 刻度槽跟着最宽刻度走**：槽宽 = 最宽标签实测宽 + 4，夹在 30–64 之间（原为固定 38）。四位量程（`1024`）不再被裁，量程变小则把几个像素还给图。

这一轮的证据：`tools/preview/out/ui-ring2/`、`.../compare/ring.png`（上=4px、下=10px，2× 局部）。

## 未改与原因

- **卷占用卡 126 px 只露 1 行 + 页脚**：卡体 77 px 装不下两行 44 px 的行 + 16 px 页脚；要么牺牲页脚要么牺牲一行，本轮保留"最该处理的那一卷 + 6 个卷/阵列状态"的读法，更全的列表在存储页。
- **配对页键区下方留白、关闭键居中**：键位数固定（12 键 + 槽），等键位/步骤变化时再重排，避免为一次性布局写特判。
- **诊断与详情滚动到折线时切半行**：可滚动容器的固有折线；要"整行折页"需要新的分页构件。
- **顶栏「配对/设置」不描边**：保持外壳安静；触控目标高度 44、位置稳定，文字即动作。信号格与状态点的语义未动。
- **「Wi-Fi 未配置」时信号格仍亮 4 格**：预览桩 `fnos_net_rssi()` 固定返回 −54，不是界面逻辑；实机驱动在未连接时给 0，信号格全暗。
- **告警健康态 2×2 体检瓦片贴顶、下方约 140 px**：属于"看住了什么"的内容设计，不是排版缺陷，留到内容轮次。
- **图标不再加"灯效"**：RGB565 硬件无渐变与阴影，圆环/图标的"发光"只能靠叠色块，会把 1024×600 画脏；保持纯笔画。
