# 全界面刷新与触控回归（2026-10-20）

范围：ESP32-P4 7B，1024×600 横屏；基线 `0b51cba`。此次修改降低稳定数据刷新的绘制负担，覆盖六个页面及配网、配对、诊断、实体详情。保留已有输入采样、手势与库阻尼动效。主机和固件构建验证完成后，已获授权烧录并通过启动、数据采集与首页实屏检查；实机触控延迟和全部页面的持续运行验收仍未完成。

## 先查现有方案

依赖锁定为 LVGL 9.5.0 和 Espressif `esp_lvgl_adapter` 0.6.4。

- [Espressif 官方适配器](https://components.espressif.com/components/espressif/esp_lvgl_adapter/versions/0.6.4/readme)：已有显示、触摸、锁及绘制统计接口，继续复用；本次没有替换驱动、增加适配层或升级依赖。
- [LVGL 9.5.0 样式源码](https://github.com/lvgl/lvgl/blob/v9.5.0/src/core/lv_obj_style.c)：重复写入局部样式会走刷新与失效区域处理，不能把同值 setter 当作免费操作。
- 复用项目已有首页局部样式比较方法，将其移入 `ui_kit`，供其余页面共用。比较的是对象的显式局部值及对应 part/state，不能用继承后样式相同来省掉必要的显式覆盖。

应用 `emilkowalski/animation-performance` 的测量与减少无效更新原则；实际实现全部使用原生 LVGL C 接口。

## 根因与修改

1. 每次数据刷新重复设置颜色、字体、透明度、阴影、边框、flex 属性，即使数值没变也让 LVGL 重新处理样式和绘制。新增共用 `uk_style_num/color/font`，只在局部值变化时写入，没有额外的对象缓存。
2. 温度池每轮强制重排，先恢复基础行距，再由 viewport 填充逻辑撑开，反复使整块温度池失效。复用既有 `inventory_shape`，比较解析后的实际几何；设备身份、名称、通道数量及展开变化仍触发布局。
3. 原性能断言只限制首页。现在六页和常用弹层都受预算约束，并明确检查弹层所在页面与内容可见性。

保留口令隐藏时先移除明文的无分配路径，以及配对信任流程。没有以跳过数据刷新、截断硬件清单或压缩动画时长换取数字。

## 已授权烧录与启动检查

2026-10-20 用户明确授权烧录后，确认实际芯片 ESP32-P4 rev3.2、32 MB Flash。先读取 `0x0..0x910000`，覆盖现有启动区、分区表、NVS 与完整应用分区；备份只留本地、权限 0600，不发布。

`flash-idf` helper 达到固定 120 秒超时后，确认烧录进程已经退出，再运行官方 esptool `verify_flash`。启动程序（0x2000）、应用（0x10000）和分区表（0x8000）均返回 `digest matched`，校验进程退出 0，因此没有重复烧录。应用 SHA-256 为 `e5dc63955165144881282c31bd739769e21dc8ba5f2e0069708be8a06d5b7fab`。

重启后采集 30 秒串口日志，成功计数从 60 增加到 150，失败始终为 0；未观察到崩溃、断言、栈保护或看门狗标记。通用监视脚本因 `fail=0` 的关键词返回 1，以上结论来自原始日志，而非该脚本退出码。`capture-board` 成功唤醒相机并取得新图，已查看实际开发板首页：页面、数据、连接状态正常可见。照片存在旋转和反光，仅支持首页显示检查，不支持闪烁、帧率或触控延迟结论。

本地烧录与回滚证据在 `tools/preview/out/perf-flash-20261020/`，相机图按约定保留在本机 board-camera 目录；均不作为公开源码附件。

剩余：六页及关键弹层的实机持续运行、真实触控响应与刷新耗时对照。主机虚拟时钟、脏区像素降低和一次首页照片不能代替这些验收。
