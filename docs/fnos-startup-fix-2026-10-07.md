# 插件 1.2.3 启动、升级与管理页修复

1.2.0 在 NAS 上启动后立即退出。实际检查发现 root 模式安装或升级会重置私有数据 ownership；日志、TLS 文件和配置备份为 root 所有、权限 0700，而管理服务会永久降权为包用户，因此无法访问。root 入口、系统 Python 及逐级父目录的信任检查通过，无需放宽检查。

1.2.1 增加前台私有数据迁移及访问预检。路径仅来自本应用 root 持有的正式 var/etc 系统绑定；遍历以目录 FD 锚定，拒绝符号链接、硬链接、特殊文件及其他用户的文件。迁移仅改变 ownership/mode，不改配置或证书内容。目录遍历时收紧 ACL，成功或异常都交回包身份，私有目录 0700、文件 0600。随后以实际服务 UID/GID 检查可访问性；失败原因直接显示在应用中心。

第一次 1.2.1 升级还暴露了临时目录问题：fnOS 从 appcenter-downloads 的新包执行 upgrade_init，而非已安装 cmd。最终实现从当前包 manifest 读取并验证应用名，再定位正式 `/var/apps/<appname>` 绑定，不再按临时脚本位置寻找数据目录。

1.2.2 修复桌面入口缺失 URL，避免管理窗口嵌套打开飞牛桌面；服务设置在有未保存改动或正在保存时不被轮询覆盖，保存动作在发请求前冻结字段值，失败保留草稿并显示具体错误。

现场升级到 1.2.2 时曾观察到容器开关从 true 变 false，其余配置和证书不变。正常 upgrade_callback 的 setdefault 不会产生这一变化；已有配置可能被安装向导默认值覆盖，读取异常后写回默认配置也是源码中确定存在的缺陷。未取得当次回调日志，不能断言是哪条路径触发。1.2.3 同时保护这两条路径：覆盖安装保留已有配置；配置写入、升级和服务加载只允许首次缺文件使用默认值，其他读取/JSON/对象类型错误明确失败并保留原文件。独立配置回调仍允许用户明确关闭容器采集。

管理服务继续使用非 root 身份。root 辅助进程只接受继承 socketpair 的单字节读取指令，仅调用固定的 Docker GET，返回受限状态字段。
