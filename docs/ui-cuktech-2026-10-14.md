# 全界面 CUKTECH 仪表语言

## 设计合同

设备为 ESP32-P4 7B，横向 1024×600 LCD、RGB565、触摸与左右滑动；以桌面近距离读数为假设，保留夜间模式。沿用既有刷新、采样、缓冲与启动首帧路径，不因皮肤改动提高采集频率。按用户最新要求，只迭代和验收当前开发板 1024×600 横屏，不再开展窄屏与竖屏版本；实体清单仍不能缩字或遗漏。

数据来自现有 fnOS 快照与真实采样历史。CPU / 内存百分比、容量、吞吐、温度、容器状态和事件使用现有单位、阈值与模块有效性判断。真实零值、未采集、部分可读、旧值和离线继续区分；不补假波形。设备顺序沿用采集器稳定顺序。

采用 `cuktech-screen-ui` 的仪表语法，最终视觉为 ULTRA 黑底白字、蓝青强调与朱红异常。默认主题为 `cuktech-console`；主数字白色，历史保持指标身份色，当前占用率由局部弧/条表达。当前令牌与设计取舍见 [ULTRA 设计](ui-cuktech-ultra-2026-10-14.md)，发布和烧录证据见 [本轮归档](ui-ultra-release-2026-10-14.md)。

## 全界面范围

| 界面 | 主问题与呈现 |
|---|---|
| 总览 | 九张等宽等高卡：CPU / 内存圆环与百分比、设备摘要；独立 CPU / 内存历史与温度趋势；网络读数、存储容量和卷占用比较。图表优先，网速曲线仅留网络页 |
| 存储 | 容量总量 + 卷 / 阵列 / 磁盘的对象单元，详情承载长诊断 |
| 网络 | 双向主读数 + 大面积趋势，合计与采集延迟次级 |
| 系统 | 容器活动状态与硬件温度并列，完整清单自适应 |
| 温度 | 最大温度 + 历史，按设备分组的统一量程温度条 |
| 告警 | 等级、事件与健康状态单元，颜色之外保留事实文字 |
| 设备详情 | 选中实体身份、完整指标、返回列表 |
| 设置诊断 | 黑底分组遥测与统一操作控件 |
| Wi-Fi / 配对 | 统一焦点色、输入框、键盘与按钮；连接、指纹、失败信息完整 |
| 启动 / 等待 / 离线 / 夜间 | 共用皮肤，数据可信度优先于装饰 |

总览采用 3×3 九张等宽等高卡：当前指标（CPU / 内存 / 设备状态）、历史图表（CPU / 内存 / 最热温度）、对象比较（网络 / 存储容量 / 卷占用）。CPU 和内存的当前占用仅由百分比和圆环表达，历史曲线移到明确标注“趋势”的独立卡片；历史图表集中在中排，读数与状态文案保持紧凑。CPU 核数、负载、队列与内存可用量、总量、交换用量直接可见，历史峰值置于趋势标题旁。温度图明确标注为传感器历史，读取与温度页相同的真实通道最高温样本；当前最高温继续允许 CPU 来源获胜，卡内保留来源名称。卷比较列数由可用宽度和可读宽度预算计算，清单完整保留并滚动可达。所有卡片共享按当前可见内容计算的最小高度，三行平均分配可用高度，不改变共享动效、采样或数据可信度判断。

九宫格验证：1024×600 正常夹具中，九张卡宽高差不超过 1 像素、页面无滚动且全部完整可见。完整预览、动态硬件矩阵、分配失败恢复、保留块可用容量、容量卡旧值/部分可读及温度来源区分回归通过；数字/圆环连续动效、六页数值与单位锚点、首次系统页切换回归通过。ESP-IDF 构建、新 ELF 静态栈预算与 RISC-V GCC analyzer 通过。本轮九宫格仅完成主机与构建验证，尚未烧录，不引用下方上一轮告警收敛的实机证据作为本轮验收。

采集告警集中在“告警”页：总览不再创建顶部结论带，日常底部告警带不显示，系统页不再重复事件列表或严重度计数；释放的空间交给遥测卡片。告警页保留等级筛选、完整事件、健康体检及采集端省略项目提示。连接状态与各指标的数据可信度仍就地显示；界面内存不足造成设备未显示时，保留全局异常提示。

本次告警布局收敛验证：完整主机预览、动态硬件清单、分配失败恢复及首次系统页切换通过；ESP-IDF 5.5.3 实机配置与独立占位配置均构建成功，静态栈检查通过。ESP32-P4 rev3.2 烧录完成，三处写入哈希校验通过；随后 25 秒运行观察未见崩溃标记、采集失败计数为零。相机实屏已确认总览上下重复提示消失；这不替代其他页面的完整物理触摸验收。个人固件、原始日志和照片只留本地，未纳入源码发布。

外壳使用底部固定页导航，释放整屏宽度。没有筛选的页面省去重复页标题；带筛选的页面保留短标题和分类。对象区域根据可读列宽排列，长名称换行、多设备滚动，保持数据可达。

通过共享调色板、卡片、对象行、按钮和字体资源覆盖上述全部界面。默认主题改为 `cuktech-console`；既有调色板仍可选择，几何与组件语言统一。
