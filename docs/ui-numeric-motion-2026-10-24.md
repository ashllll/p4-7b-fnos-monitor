# 数字快速跳变：呈现节拍修正

用户反馈：接收数据后，数字变化过快且像不规则跳字。此项与拖动 FPS 分开验收；旧的高 FPS 和整屏触控缺口继续保留。

## 原因与修正

实际路径为 `ui_tick → refresh → uk_number_refresh_begin → uk_number_set_reading/set_text → LVGL animation`。开发板遥测请求周期为 200 ms，数字呈现间隔却为 0；名义 600 ms 的变化可在每次新读数时重定向。设备还保留逐位错峰 50／100 ms、25% 字高位移及 6% 模糊的旧配置。位置和速度连续性自检通过，但这些设置仍使屏幕持续翻字，不能靠“有阻尼库”判定体验顺滑。

| 原配置 | 修正后 | 目的 |
| --- | --- | --- |
| 每个 200 ms 采样都可换字 | 数字共用 600 ms 呈现节拍 | 每次选择最新真实读数，给读数留出停稳时间 |
| 阻尼比 0.85 | 临界阻尼 1.0 | 避免静止起步时的欠阻尼回摆 |
| 位移为字高 25% | 字高 4% | 减少翻滚幅度 |
| 逐位错峰 50／100 ms、模糊 6% | 错峰与模糊均为 0 | 同一读数一起变化，减少重影与额外绘制 |

继续使用现有 Ryan Juckett Damped Springs 和 LVGL 调度，不改求解器或另写插值算法。名义响应时长仍为 600 ms；这不是匀速运动或每一帧均分的时长。首次有效值、缺失、单位／状态改变、隐藏与精简动效沿用即时发布；采集、历史和告警不受数字呈现节拍限流，不插值历史，也不排队重播旧读数。

Kconfig、`sdkconfig.defaults` 与 `uk_theme.h` 无配置时的回退值已对齐。已有 `sdkconfig` 不会因默认值变化自动迁移，本次开发板配置已显式更新；后续升级需检查对应 `FNOS_UI_NUMBER_*` 和 `FNOS_UI_TELEMETRY_RATIO_PERMILLE` 项。`NUMBER_PRESENT_MS=0` 继续保留为显式关闭呈现节拍的选项。

## 验证记录

在既有 `PREVIEW_NUMBERS` 中增加快速输入回归，使用真实数字控件接口、确定性的 LVGL 时钟及匿名样本：3 秒输入 15 次，检查配置的最小呈现间隔、取最新目标、单位配对和缺失值即时发布，并输出逐帧图像。

修正前实际得到 **15 次换值，最短间隔 200 ms**；“3 秒至多 6 次换值、间隔至少 500 ms”的本次可读性对照失败。修正后同样本为 **5 次换值，最短间隔 600 ms**，逐笔目标和准确次数均通过，不会把停更误判成稳定。显式 0 ms 选项仍得到 15 次换值／200 ms。该对照检查逻辑呈现节拍，不证明数值源平稳或实机帧率。

完整预览另外抓到首次实时读数被关闭节拍挡住的边界：同步预填使用上一份快照时，下一笔新读数可能等待下一拍。新增回归先失败，再在数字控件内记录一次同步标记；第一笔实时更新消费标记，后续恢复共享节拍，不重开全局节拍。值／单位只保留一处呈现判断，相同单位不再重复发布。

正常构建、所有入口静态栈、RISC-V GCC `-fanalyzer`、ASan／UBSan 数字回归、完整 131 张状态与 10 张刷新图及硬件清单／分配失败恢复通过。六页数值动效覆盖 28 组数值／单位锚点，首次系统页 71 帧、重复目标 96 帧通过。ASan 本轮关闭 LeakSanitizer，图层分配／释放数量仍由原自检覆盖。新鲜数字逐帧图已查看，减少了垂直翻滚与错峰；跨位进位仍会短暂交叠，不能用单帧或主机换值次数宣称实机动效已经顺滑。

发布目录使用独立构建和新的 `SDKCONFIG` 从默认值生成配置，模板构建通过；实际参数为 600／600 ms、阻尼比 1000、错峰与模糊 0、位移 4%。采用 ESP-IDF 5.5.3 及其支持的 GCC `esp-14.2.0_20251107`。首次新构建因 PATH 指向不匹配的另一工具链而被官方检查拒绝；调整为支持版本后重建，没有关闭版本校验。

## 实机与当前边界

正常候选 ELF 为 `30fbc67eac414dfd74dfba17a2933d851ef123a4a8250c7afa6a8dad6375b7c8`。三个烧录区域校验通过，未擦除 NVS；从复位开始核对固件身份及在线门。750 次采集成功、零失败，十二次脚本拖动零漏计，无崩溃、Wi-Fi 找不到或绘制缓冲回退标记。

本窗口首页／网络／系统每页两轮拖动 P50 间隔的均值分别约 48.898／44.550／39.434 ms，其倒数约 **20.5／22.4／25.4 FPS**；这不是合并所有帧样本后的 P50，也不是光学帧率。不拿不同时间、数据负载下的小差异判收益或回归；切页高 FPS 目标仍未通过。

首页／网络／首页三张新鲜实屏照片均已查看，可见读数及对齐正常，仍有倾斜和右侧裁切。相机曝光期间出现的字形交叠不等于面板撕裂证据；静态照片也不能证明持续数字动效自然。**T10 的实现、自动回归和烧录完成，用户肉眼体验待确认；完整触控、光学帧率与长稳仍开放。** 代码及文档保存在独立发布目录的明确文件清单中，尚未暂存、提交或推送 main。

私有配置、个人固件、原始串口日志和相机照片留在开发目录 `.local-artifacts/numeric-motion-20261024/` 及本地拍屏目录，不进入源码发布。
