# NAS 硬件数量与名称自适应

本轮处理 NAS 配置差异，涵盖采集、传输、快照和原生 LVGL 界面。使用 ui-skills 路由下的 interface-design，保留已有视觉方向与间距令牌。

开发目录为 `p4-7b-fnos-monitor`；资料仓不参与修改。已有脏工作区保留，未提交、推送、发布或安装到真实 NAS。

## 实现契约

- 卷、阵列、磁盘、温度通道、容器和网口按实际条目数处理，生产代码不再使用设备数量固定数组或固定显示条数。
- 名称、挂载路径、设备与温度通道 ID 动态存储；完整身份用于排序与分组，不以截短显示名称辨识设备。
- 采集器默认传送完整清单。若调用者显式设置数量策略，仍提供真实总数与遗漏数量。修复温度清单先裁剪、统计逻辑不可达的问题。
- 所有网络接口除 loopback 外分别采集，速率按各接口计数器与单调时间计算；热插拔、计数器复位时不产生负速率。默认接口摘要继续兼容旧固件，新增清单位于 `net.interfaces`。
- HTTP 缓冲按实际帧增长。快照以原子引用保留清单所有权，使用 `create/text/parse/copy/release` API；解析失败时不替换最后有效快照。
- 卡片列数由可用宽度、主题首选宽度、真实名称与数值需求决定；高度按文本与内容测量。清单独立滚动，短屏可滚动整页，空清单显示空状态。
- 温度按完整设备身份分组，多通道通过手动展开查看；传感器增减不自动跳切。分组分配失败时保留已复制的界面内容与展开状态，下一帧成功后恢复。
- UI 清单与文本分配失败时仅访问实际成功创建的条目，并显示“界面内存不足 · 部分设备尚未显示”，不能把部分显示伪装成完整清单。
- 总览计数与存储容量按完整字符串测宽选择字号，必要时换行；网络累计流量自动换单位。总览左右卡片与下方卷列表都保留内容最低高度和可拖动空间。

## 有限资源与状态表达

| 配置 | 默认 | 行为 |
|---|---:|---|
| `CONFIG_FNOS_STATUS_MAX_BYTES` | 262144 B | 限制整帧字节，不限制设备条数；超预算明确报错，保留上次快照 |
| `CONFIG_FNOS_SNAPSHOT_MAX_BYTES` | 1048576 B | 按需分配清单与字符串；预算耗尽拒绝整帧，不截尾 |
| `CONFIG_FNOS_UI_LIST_MIN_WIDTH` | 项目主题配置 | 决定首选卡片宽度；列数由实际可用空间推导 |
| `FNOS_FONT_CJK_RANGES` | 基本汉字、横排假名、拉丁扩展、希腊、西里尔 | 字库覆盖可扩展；不声称包含任意 Unicode 字符 |

字库生成同时扫描固定文案。CJK 使用未压缩 2bpp，避免设备两路绘制共用 RLE 解码状态；标签和顶栏按真实字库行高占位。

来源的离线、旧值、权限不足、缺失和读取失败保留独立状态。旧采集器的截断元数据会提示；旧应用未提供全部网口时，只能显示已提供的数据。
