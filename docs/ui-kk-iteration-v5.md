> 状态：**V5.0-A/B/C/D + V5.1 + V5.2 已实施**（manifest + 生成物 + Controller + 字库），待实机复验（§5.7）。

## 0. 三个方向如何共存（分工，不打架）

三个方向如果平摊到每个像素上会互相抵消：密度要更多字段、大数字要更大字号、对齐要更"像 NAS"。
因此按**层**分工，每层只由一个方向说了算：

| 层 | 由哪个方向主导 | 只管这些事 | 明确不做 |
| --- | --- | --- | --- |
| L1 版面语法 | 信息密度优先（Beszel / Grafana） | 卡片网格、空白槽位利用、图例与统计合并、每行字段数 | 不改行高、不改卡间距、不加页面 |
| L2 数字排版 | 极简大数字（车载 / AIDA64） | 数值字号、单位弱化、数字列右对齐、标签与数值的主次比 | 不放大小字标签、不动元信息字号 |
| L3 术语与信息架构 | 与 fnOS 原生对齐 | 文案、字段命名、存储层级（存储空间 / 硬盘 / 阵列） | 不照搬 fnOS 配色 |

**为什么 L3 只对齐术语、不对齐配色**：fnOS 网页端没有深色主题（官方论坛里的功能请求：*"网页端没有深色主题，希望加上。"* —— https://club.fnnas.com/forum.php?mod=viewthread&tid=16781 ），
而本板是深色常亮面板，配色继续用 KK 令牌（`KK_BG 0x080B10` / `KK_PANEL 0x161E2B`）。对齐落在"用户看惯的词与结构"，这才是第二块屏的价值。

### 6.1　v5.1 修复：删掉温度卡两条"全高竖刻度"

**用户报障**（原文）："系统界面 温度模块有两条竖线bug 需要处理解决 一直在显示着"。

**定位**：P3 温度卡里只有两个 1px 宽的 `Divider` —— `SyTTick60`/`SyTTick75`（`SyTempPanel` 子节点，
尺寸 **[1, 378]**，位置 [172,44] / [183,44]）。它们是 v4.2 B7 "温度栏 60/75 档刻度"的产物，
x 坐标本身没错（温度条卡内 x=126..202，76px 宽 ⇒ 60% = 171.6、75% = 183）：错在**长度**——
378px 等于 10 行行高之和，于是这根 1px 灰线（`#334052`，Divider 默认色）纵穿所有行底与条轨，
且数值文字框卡内 x=148..228（右对齐的 `73.0°C` 实际占 ~183..228），刻度正好贴着数字左缘，
静止不动 ⇒ 既不像刻度、也不像分隔，只像渲染残迹。

**修法**：删除这两个节点（`/tmp/patch_ui_v51.py`，断言几何/父节点/无子节点/无其他文件引用后写盘，
原 layout.json 备份 `/tmp/v51_backup/layout.json`；改后 `layout.json` −1456 B、−50 行）。
保留分级语义的两条既有通道：**数值文本**（`73.0°C`）与**条的分级色**（`KK_BAR_WARM/FULL`，实测
73°C 走黄、33°C 走青）；容量页的 `StVolTick60*/85*`（1×18，被约束在行内）不动。
不新增字库、不动任何其他节点 ⇒ `ui_validate` 只需 nodes 393 → **391**。
