# Device 风格：NAS 内容与原生动效

参考：[KindofDevice 的演示视频](https://www.instagram.com/reel/DdZMx18NM6z/)。
用户选择复刻视觉与动效，内容继续使用 NAS 数据。实现位于 `fnos_ui.c` 和原生 LVGL `ui_kit`，没有引入第二套 Web UI。
设计评审使用 `interface-design`，动效参考 `emilkowalski/animate`。

## 视觉与内容映射

- 深紫黑背景、薰衣草色数字、低圆角薄间隔、薄荷绿主块与桃色摘要块。
- 原视频的时钟区域改为 NAS 运行时长（HH:MM 是天数之外的小时与分钟），不伪造当地时间。
- 原天气与 Dock 辅卡改为内存历史、容器运行状态；下方展示网络历史和存储容量。
- 五个数据页面与配对入口排列在底部。系统页采用桃色摘要和统一底色的列表；矮屏按实际高度转为多列。
- 未采集、离线、模块权限不足、旧历史等状态仍来自采集快照；动画不产生采样值。

设计令牌集中在 `ui_kit/uk_theme.h`，颜色集中在 `uk_theme.c` 的 `device` 预设。
默认主题由 `CONFIG_FNOS_PALETTE` 选择；其余主题仍可使用。
数字字体采用 SIL OFL 授权的 Chakra Petch Bold 子集，许可在 `fonts/ChakraPetch-OFL.txt`。
视频没有提供原始字体或布局资源，因此字体、色值和曲线是基于可见画面匹配，不是已证实的原始参数。
原视频接近方屏，开发板是 1024×600 横屏；信息布局按原比例关系自适应。

## 原生页面控制器

内容视口裁切两张相邻页面。横向位移跟随 pointer，松手后提交或回弹；纵向操作交给列表滚动。
短滑不换页，快速反向从当前位移衔接，当前页重复请求会结束暂停的切页。
进入系统页前先完成内部布局；打开配对、诊断或 Wi-Fi 覆盖层前先落定页面。

页面位移使用闭式临界阻尼，快速反向承接当前帧的速度。按剩余位移选择
`UK_MOTION_MIN_MS` 至 `UK_MOTION_MS`（80–160ms），零距离直接落定。
导航期间卡片内容保持不透明，取消原先最长 255ms 的错峰显现，避免软件透明度图层和内容延迟。
横滑识别阈值按视口宽度百分比计算，并保留最小触摸距离和纵向滚动隔离。
`CONFIG_FNOS_UI_REDUCED_MOTION` 可在松手时直接落定；夜间模式保留暗色与边框设置。

原视频未提供可供像素级比较的原始 UI 资源，因此当前结果是已落地的视觉/动效匹配，仍不能宣称原参数的一比一验收。

通用构建/烧录 helper 未识别本机项目包装环境，使用已验证的 `./idf.sh` 完成。
已将该入口记录到忽略的项目 Profile；后续全局安装的 helper 需显式传 `--workspace` 指向本工程，
已回读确认其可以识别项目包装入口，避免把全局 skill 的软链接目录当作工作区。
串口监视 helper 用于设备发现；连续切页取景复用项目 `page_shot.py` 的 DTR/RTS 电平规则，
由单一串口进程保持正常运行电平并收集本地日志，避免打开端口后进入下载模式。

## 动效响应优化（2026-10-08）

- 翻页只检查目标页的布局；首次数据到达或条目数/视口尺寸改变时，提前准备隐藏页的几何。
  预排版由同一 LVGL 任务完成，页面临时移出裁切视口，返回渲染器之前恢复隐藏状态。
- 8ms 手势调度沿用原生输入定时器的实际采样。偏移不变时不重绘，按钮按下立即给选中表面反馈。
- 翻页期间继续消费真实采样和历史游标，仅延后文案与池刷新；结束时消费待刷新标记。
  重复请求当前页不会重复刷新，顶栏页名随导航立即更新。
- `CONFIG_FNOS_UI_MOTION_STATS` 默认关闭。开发配置可开启只含准备耗时、渲染耗时、帧数和归位时间的聚合日志，
  不输出端点或采集内容。`elapsed_ms` 从准备开始量至控制器归位，不能视为手指到屏幕的端到端延迟。

原生自动输入读取测试使用固定 32ms 响应、180ms 归位预算，不跟随生产时长令牌自动放宽。
三尺寸均通过：小横移首次跟手 17ms；短滑松手归位 102–105ms；快速短划 163ms；
API 翻页完整归位 166ms；最后一次快速反向 160ms；首帧内容已可见。
测试冻结 NAS 时钟和采集序号，不能用这些虚拟时间数字宣称实机帧率。

225 张状态预览、三尺寸各 151 帧动效、71 帧首次系统页、96 帧暂停后重复当前页回归通过。
当前 ELF 任务静态栈检查通过；物理测量记录见本段末尾的实机对比。
匿名逐帧播放器位于忽略目录 `tools/preview/out/motion-v2/motion/index.html`。

同一开发板、同一串口切页序列，每组 11 次切换的最终实机对比：

| 聚合指标 | 优化前 | 最终固件 |
| --- | --- | --- |
| 准备耗时中位数 | 86.8ms | 7.75ms（减少 91%） |
| 首次系统页准备 | 478ms | 11.1ms |
| 准备至控制器归位中位数 | 331ms | 188ms（减少 43%） |
| 单次渲染耗时中位数 | 42.2ms | 36.1ms |

最后烧录的三个分段均校验成功，当前 ELF 静态栈预算通过。
最终五页相机取景已实际查看，页面、选中导航和顶栏名称一致，没有发现错位或前页残留；
两次总览取景中的运行时长、轮询数和网络读数继续变化。串口记录达到 90 次成功轮询、0 次失败，
未见 panic、栈保护、看门狗或断言错误。原始记录和相机取景仅留本地。
这些耗时由固件的 LVGL 渲染事件和控制器统计，不包含串口调度等待或触摸到面板扫描的全部链路，
也不能用静态取景宣称 60fps、无撕裂。用户随后已于 2026-10-08 验收这版动效。

性能复核使用 DSH Desktop，只读审查和 OCR 文件/规则筛选均已收尾；主代理修正其无效的
`indev PRESSING` 建议，并验证窄屏测试、待刷新消费和持续历史采样的补充修正。

## Refactoring UI 视觉优化（2026-10-08）

在已验收动效上使用 `gnurio/refactoring-ui-plugin` 的总评、视觉层级和对比度技能。
提升 CPU 与底部导航的字号，减弱重复标签和边框，修正夜间桃色卡片及主按钮文字对比度。
系统摘要直接显示采集状态，空告警按实际文字高度收缩，将空间让给容器与硬件温度；
共享列表重排保留采集器顺序。三尺寸与四主题静态检查、既有动效回归均通过。
完整问题清单和本轮实机验证见 [视觉优化报告](ui-refactoring-ui-2026-10-08.md)。
