# 三批 UI 问题整改与实机验收（2026-11-08）

本文记录 2026-11-08 这一轮"界面还有哪些值得改进"的排查结论与整改结果。11 项问题按三批推进，每项走 TDD（先写会红的断言、再改实现）+ SDD（先定问题与验收，再落代码），全部在 1024×600 横屏上验证。

## 结论

- 11 项全部修完，主机四项审计（字形覆盖 / 标签溢出 / 子对象越界 / 可点击重叠）+ 对比度 + 稳态零脏区全过：`bash tools/preview/run.sh out/audit-final3` exit 0。
- 固件用官方 ESP-IDF 5.5.5 重编并烧进 ESP32-P4 7B（rev v3.2），六页 + 两层覆盖层都有实机像素证据。
- 栈深（新 ELF）：`cli_task` 2608/4096 = 64%、`probe_task` 35%、`ui_retry_task` 33%，全部在预算内。

## 实机像素取证

板上没有快门、`capture-board` 装不上、macOS 也不给相机权限，所以固件里加了验收命令：

- `shot`：把当前页 `lv_snapshot_take()` 成 RGB565、2×2 盒式平均降到 512×300，base64 走串口（`SHOT-BEGIN/END`）。`tools/shot_pull.py` 收帧、校验行宽、写 PPM。
- `shot pair` / `shot detail`：配对卡与实体详情抽屉只能点开，这两条子命令先让 UI 线程摊开覆盖层（配对卡走顶栏按钮同一条路，详情取当前页第一行），等动效落定再截。
- 吐一帧 400 KB 要 40 秒，这期间任何日志都会插进 base64 行把行撕碎（实测 66 行坏 3 行），所以 dump 期间把根日志级别压到 `ESP_LOG_NONE`，结束后逐个 tag 恢复。

六页 + 覆盖层样张在 `tools/preview/out/board/`（本地生成，不入库）。实机判读时又补了两处：
已配对态下配对卡只画到一半（补"单排铺满容器"）、这台板子的 NVS 里本来就没有存指纹 ——
正好把"未保存证书指纹 · 地址"这条占位路径在真机上跑通了，而不是留一张空白卡。

## 记在心里的坑（详见 MEMORY）

- `ESP_IDF_VERSION` 必须写 **5.5**（不是 5.5.5），否则 esp_wifi_remote 的 `orsource` 会静默跳过整段 Wi-Fi 配置。
- 拿旧 `sdkconfig` 配新 IDF 要看 `build/config/sdkconfig.h`：choice 型符号（ESP-Hosted SDIO/SPI）会被静默改写回默认值，症状是 `E transport: Not able to connect with ESP-Hosted slave device` 且 `app_main` 卡在 `esp_wifi_init`。
- 串口独占：烧录与任何串口读取并发 = `The chip stopped responding` 烧录失败。
- `LV_LABEL_LONG_MODE_DOTS` 会就地改写 label 文本，首帧宽度解析为 0 的 label 会被永久截断；给 label 定宽要用 flex grow 子项。
- LVGL 的 flex 没有 cross 轴 stretch，等高卡片必须手动分组取最大高度。
- 字形范围只有 `0x20-0x7E, 0xB0, 0xB7, 0x2014, 0x2026, 0x2190-0x2193, 0x2264-0x2265` + CJK：● / ▸ / ▾ 都没有，用了字形审计直接 abort。
