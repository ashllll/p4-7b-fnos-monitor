# 动画技能复核：数字与仪表同拍

日期：2026-10-24。目标为 ESP32-P4 7B、1024×600 横屏；基线为 `62730fc` 对应的原生裁剪揭示固件。本轮按用户指定的 `esp32-small-screen-anim` 技能检查并优化，交付分支为 `esp32-small-screen-anim`。

## 采用的成熟方案

技能自检为 **8 passed / 0 failed**。采用 §3 的采样与显示分离、§4 的可变时间步稳定响应、§7 的 LVGL 动画生命周期检查。继续使用已有 Ryan Juckett 闭式阻尼弹簧和 LVGL 原生动画、圆环、条形及裁剪；不另写求解器或切换绘制栈。P4 具有单精度 FPU，且本板走 MIPI DSI，技能针对其他 ESP32 的“无 FPU”和 SPI 预算前提不套用到本板。

本轮最值得修正的是**数字已经守 600 ms 呈现节拍，圆环与条形仍逐笔接收新目标**。持续输入时，仪表比同一读数的数字更早追新目标；单纯加长动画时长会继续被采样打断。

## 实现与回归

- 数字和仪表共用原有呈现门。关门期间保留上次呈现目标，已有弹簧继续运行；下次开门只取最新样本，没有积压队列。600 ms 节拍及响应参数不变。
- 真正的首次有效值立即发布，并消费预填旁路；随后普通样本守门。显式预填、旧值、缺失、隐藏和禁动效仍即时发布；缺失恢复后的后续采样不会额外绕过节拍。
- 行身份或单位改变时，文字和条形一起立即更新。卷和温度摘要转为旧值时，先发布当前保留值，再停止动画，避免文字已更新而条形停在更早的值。
- 源采样、历史、告警判断、图表时间轴与拖动裁剪揭示均保持原合同。未调整已验证的弹簧求解器和切页时长。

回归使用既有公开控件接口和真实页面刷新路径：旧代码在闭门时出现“数字 11、条形目标 12”；补齐旁路后，又以“无预填首值 10→11”和“缺失恢复 30→31”验证正常后续采样会被挡住。设备 A→B 复用行、真实卷旧值更新均有先失败后通过的证据。临时撤回旧值发布修复时，真实卷页面的条形数值断言失败；恢复修复后，卷和温度两条真实页面路径均通过。

## 继续改进的边界

典型拖动帧距保持接近 60 Hz；P95 仍约 31–35 ms，**全程锁定 60 FPS 未通过**。后续优先拆分准备、拖动、松手与补刷的长帧，再决定是否需要调整收尾曲线；本轮没有凭观感猜测更换弹簧参数。真人手指触控、完整无遮挡取景、长时运行与故障注入仍分别验收，不能用这次脚本和短测替代。

复现本机检查使用 [preview 入口](../tools/preview/README.md) 的 `PREVIEW_NUMBERS`、`PREVIEW_DATA_MOTION`、`PREVIEW_MOTION_RESPONSIVENESS` 与完整 `run.sh`；主机采样步长不代表实机 FPS。
